素材库在这

你下载的东西全进这里：能搜、能筛、能预览。 它是一个独立页面，不是这个弹窗——弹窗一关就没了。

点「打开媒体库」→ 新窗口打开库页；点「放进收藏夹」→ 按钮变 ✓ 已在收藏夹

1
为什么用蒙层而不是顶部小条——你要的是「大字」。小条会被列表淹没，用户照样找不到；蒙层是唯一能让人停下来看一眼的形式。
2
只弹有限次——不是每次点开都弹。完成任一动作（打开 / 加收藏 / 我知道了）就永久不再弹；都没做的话最多弹 3 次，之后自动静默，不骚扰。
3
不挡主流程——蒙层右下角留一条「我知道了」，随时能关掉去下载。看完这眼就能正常用。
4
收藏夹按钮是真一键——已实测：扩展能在 popup 里直接写书签，连点两次会产生两条重复书签，所以会先查重，加过就显示「已在收藏夹」。

1
和引导层分工——引导层负责「第一次知道」，胶囊负责「以后随时能找到」。两个都要，只做一个都不够。
2
顺手修一个真 bug——popup.html 里 vrOpenLibrary 这个 id 写了两遍（顶栏图标 + 工具抽屉里那个「资源库」按钮）。getElementById 只认第一个，导致「设置里关掉媒体库入口」的开关只关得掉顶栏那个，抽屉里那个照旧显示。
3
不新增设置项——这个胶囊跟随现有「启用媒体库」开关，关掉就一起隐藏，不再加新开关，避免设置页越堆越多。

问题根因

不是「入口藏得深」，是从来没有告诉过用户有这么个东西。

装完打开的欢迎页整页讲功能、隐私、免责，零处提到媒体库；popup 里它只是第 3 个灰色小图标。用户自然以为这扩展就是「点一下、下个文件」。

技术前提（已实测）

  • 扩展能在 popup 里直接写书签，无需用户手势
  • 能写入 chrome-extension:// 地址，并读回验证
  • 收藏栏节点 id 为 1（Edge 实测，Chrome 一致）
  • 按 URL 查重可用，避免重复添加

踩到的坑

连点两次「加入收藏夹」会真的产生两条一模一样的书签——浏览器不查重。所以必须自己先 search 再决定加不加，已加过就显示「已在收藏夹」。

三层分工

① 装完那一眼：欢迎页大卡，讲清楚「在哪 + 怎么收藏」。

② 点开图标：大字蒙层，完成首次认知。

③ 长期：顶栏金色胶囊 + 收藏夹书签，两个常驻入口。

不改的东西

嗅探、下载、命名、库页本身一行不动。只加引导层和一个按钮样式，风险面极小。

可点的部分：三个 tab 切换场景；「复制地址」「加入收藏夹」「打开媒体库」「我知道了」都有真实反馈。 收藏夹按钮点一次会变成「✓ 已在收藏夹」，再点无效——这就是防重复的实际表现。
