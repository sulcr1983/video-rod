## 一、三家怎么做的（代码级证据）

### 1. 小金薯（Edge 商店，21000+ 用户，v1.0.9）

核心就 10 行，**纯 SSR 解析，零 DOM 选择器**：

```js
let n = r.match(/<script>window\.__INITIAL_STATE__\s*=\s*(.*?)<\/script>/s);
let i = n[1].replace(/undefined/g, "null");
let s = JSON.parse(i);
const o = s.note.currentNoteId;
const a = s.note.noteDetailMap[o].note;
const h = a.title, u = a.desc;
const l = a.imageList.map(t => t.urlDefault);
let c = [];
if (a.video) {
  const t = a.video.media.stream;
  t.h265 ? c = t.h265.map(t => t.masterUrl) : t.h264 && (c = t.h264.map(t => t.masterUrl));
}
```

| 维度 | 它的做法 |
|---|---|
| 触发 | `tabs.onUpdated` 监听 `/explore/` → 通知内容脚本在笔记左上角出按钮 |
| 批量 | **不做首页批量**，只在详情页下当前这一篇 |
| 命名 | JSZip 打包成 `笔记标题.zip`，内含 `title.txt`（标题）+ `text.txt`（正文）+ 图/视频 |
| 作者 | **完全没有**——zip 名只用标题 |
| 视频 | 只 h265→h264 两级，不排码率 |
| 去重 | 无（商店评价里就有人抱怨"压缩包里有两个一模一样的视频"） |

**结论**：它简单粗暴，但**取数源是对的**（state 而非 DOM）。这恰好是我们踩的坑。

### 2. 小红薯（Chrome 商店，v1.4.6）—— 技术最强的一家

做法比小金薯深一层：**注入 MAIN world 脚本 `is.js`**，用自定义事件从页面 webpack 运行时里取数据（`xhs_media_edith` / `xhs_media_edith_response`），所以能拿到 SSR 里没有的**评论区图片**和 livePhoto。

四个值得抄的点（附它的原码）：

1. **字段双写兼容**（小红书前端两套命名混用）
```js
const a = t.image_list || t.imageList;
const u = t.tag_list || t.tagList;
e.url_default || e.urlDefault || e.url
t.note_id || t.noteId
```
2. **原图域名规则**（这是"去水印原图"的真正机制，比我们用的 `ci.xiaohongshu.com` 稳）
```js
"https://sns-img-bd.xhscdn.com/" +
  url.substring(url.split("/", 5).join("/").length + 1, url.lastIndexOf("!"))
```
即：砍掉签名时间段 + 丢掉 `!nd_xxx` 变换后缀，换成 `sns-img-bd` 域。
3. **视频选档算法**（按面积优先、同面积比码率）
```js
o = e.sort((a, b) => {
  const t = a.width * a.height, o = b.width * b.height;
  return o !== t ? o - t : b.avgBitrate - a.avgBitrate;
})[0]
// 优先级：h265 → h264 → EF5 → EF4，且 originVideoKey 走 sns-video-hw
```
4. **DNR 把 UA 改成安卓移动端**（只对 `discovery/item/*` 的 XHR 生效，拿到更完整的接口字段）
```js
declarativeNetRequest.updateDynamicRules({ addRules: [{
  action: { type: "modifyHeaders", requestHeaders: [{
    header: "user-agent", operation: "set",
    value: "Mozilla/5.0 (Linux; Android 8.0.0; SM-G955U ...) Chrome/143.0.0.0 Mobile Safari/537.36" }]},
  condition: { urlFilter: "xiaohongshu.com/discovery/item/*", resourceTypes: ["xmlhttprequest"] }}]})
```

**注意**：它的"批量下载"是**付费墙**功能（`geckoinfo.cloud` 订阅制，免费 5 次）。反过来说明——首页批量下载是真实刚需，我们不能砍。

### 3. 小红书下载助手（v1.0.2）

**我们已经拆过并抄过了**：`background.js` 里 `vrXhsScanViaHtml` 的注释原文是「快路径（抄「小红书下载助手」v1.0.2）」，`vrXhsScanInPage` 里的原图候选注释是「抄「小红书下载助手」v1.0.2 的 sourceImageUrl」。这家没有新东西可抄。

## 二、我们三个问题的根因（全部实测取证，不是猜）

### 问题 ①「首页点下载，全部下载了，第二没得选」

**根因是档位过滤 bug，不是产品设计缺陷。**

`js/lib-image-util.js` 的 `tierCounts()`：
```js
var ss = shortSide(arr[i] && arr[i].w, arr[i] && arr[i].h);
if (!ss) { continue; }      // ← 尺寸未知的图被直接丢掉
```
小红书首页是懒加载：图没进视口 → `naturalWidth=0` → `ss=0` → **不计入任何档位**。

于是你截图里看到的：扫描完成 70 张，但「小 0 / 中 0 / 大 0 / 超大 0」，勾选网格是空的 → **没法选**，只剩「下载这 70 张」一个按钮 → 只能全下。

讽刺的是同一个文件里 `scanImages()` 的注释写着：

> 「未解码时 naturalWidth 为 0 —— 这在懒加载站点上是常态而不是异常……**没解码不等于不存在**」

两处逻辑自相矛盾，档位过滤这一侧把扫描那一侧的成果吞光了。

### 问题 ②「用户名、笔记名全部都是错的」

**根因：popup 批量下载走的是 DOM 选择器，而 SW 里已有 state 精确取数，两边没接上。**

- `js/naming.js` 的 `extractXiaohongshu()` 用 `#detail-title` / `.username` / `.user-id` 这些选择器 —— 小红书现在 class 是哈希值，**全部抓空**；
- 标题抓空 → 退回 `doc.title`（**页面标题**）→ 你截图 3 里 91 张全是「给水杯厂做ERP实施，我发现最难的不是系统」；
- 作者抓空 → `buildRelDir()` 用**域名兜底** → 库里作者全是 `www.xiaohongshu.com`；
- 而 `background.js` 里的 `vrXhsScanInPage()` **早就从 state 精确取到了** `note.user.nickname / redId / title / desc`，还处理了两个坑（noteDetailMap 空对象、currentNoteId 是 object）—— **popup 从来没调用它**。

**而且调不通**：`vrXhsScan` 消息用 `sender.tab.id` 取标签，但 popup 是扩展页，`sender.tab` 是 undefined → 返回 `no-tab`。这是个硬阻塞。

### 问题 ③（顺带发现，你还没提但会影响体验）

首页 feed 每张卡片属于不同笔记，但命名只用一个页面标题 → 必然全部同名。ADR-071 的白名单只解决**详情页**，首页需要**按卡片分组**取各自的 noteId。

## 三、方案（请挑）

### 方案 A：接上已有能力（推荐，最小改动）

| # | 改动 | 文件 | 量 |
|---|---|---|---|
| A1 | `vrXhsScan` 支持显式传 tabId（修硬阻塞） | background.js | 3 行 |
| A2 | popup 批量下载前先取 state 权威标题/作者，注入路径与入库 meta | popup-videorod.js | ~50 行 |
| A3 | 档位加「全部」档为默认 + 尺寸未知条目不被过滤 + 计数显示 unknown | lib-image-util.js / image-panel.js | ~25 行 |
| A4 | 首页按卡片分组命名（每张卡取自己的 noteId） | 需新增 | 中等 |

A1–A3 我已经写过一版（在 stash 里），A4 没做。

### 方案 B：抄小红薯的三件具体事（可与 A 叠加）

| # | 抄什么 | 价值 | 风险 |
|---|---|---|---|
| B1 | 原图域名 `sns-img-bd.xhscdn.com` + 砍签名段/`!`后缀 | 我们现用 `ci.xiaohongshu.com` 实测部分 ID 404；这家域名策略更稳 | 低，替换候选生成规则 |
| B2 | 视频选档：面积优先、同面积比 `avgBitrate` | 我们现在按 format→height→bitrate，基本等价，可对齐 | 极低 |
| B3 | DNR 加安卓 UA（仅 `discovery/item/*` XHR） | 接口字段更全，可能顺带解决评论图 | 中，改 UA 有风控面 |

### 方案 C：学小金薯砍掉首页批量（不推荐）

首页不给「全下」，只让逐篇打开下。能同时消掉 ①③，但**砍掉了我们的核心卖点**（苏哥你自己说过"有图片就可以单独下载或者批量，这才是我们设计的意义"），而且小红薯把批量做成付费墙，正说明这是刚需。

## 四、我的建议

**A1+A2+A3 立即做**（这三个是你截图里问题的直接解药，改动小、可验证），
**B1 一起做**（原图域名是实打实的画质收益，且我们已有 `xhs-media.js` 承载），
**A4 单独立项**（首页分组命名要动嗅探与命名两层，值得单独一轮），
**B3 缓做**（改 UA 有风控面，先不动），
**C 不做**。

另外坦白一句：关于「是否直接放弃我们的小红书模块换他们的」——**不建议**。我们的 `vrXhsScanInPage` 比这三家都强（有 SSR 快路径、空对象重试、原图候选探测、DNR 规则池、入库去重），问题不在能力，在于 **popup 这条新链路没接上这个能力**。换模块等于把已经验证过的东西扔掉，风险远大于收益。
