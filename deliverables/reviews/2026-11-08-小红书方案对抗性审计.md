## 二、stash 草稿的硬 bug（若直接取用会引入新缺陷）

**BUG-S1（无效代码）**：`vrRelabelBatchCards` 调 `vrFullPath(d, idx)`——现行 `vrFullPath(data)` **只接受一个参数**（`popup-videorod.js:808`），第二参数被静默忽略；且它用的是 `data.downFileName`（预先算好的路径），relabel 根本重算不了路径。整段 relabel 逻辑无效。

**BUG-S2（对齐错位）**：relabel 按 **index** 对齐 vrBatchPlan 与 state imageList。白名单回退时嗅探列表混入推荐流（DEF-07）、视频/图混排、去重过滤都会让 index 错位——**张冠李戴**，比现在的「全部同名」更糟（错误命名伪装成正确）。正确做法：按 URL 的 id 段匹配（net-sniff 白名单的 `xhsIdKey` 同款口径）。

## 三、方案设计本身的问题（对抗性推演）

**D-1（A2 越界）**：草稿在 popup 里 relabel 卡片+改路径——侵入 UI 状态流，且与 B-38 单写盘通道刚收口的代码耦合。**更小方案**：`pageInfo` 是 var（`popup-videorod.js:37`，2297 行赋值）——popup 取到 state 权威作者后**更新 `pageInfo.authorFull / creatorId` 一处**，下游 `vrDirOf → buildRelDir` 全链路（路径、卡片名、入库 meta）自动继承正确值。改动量约为草稿的 1/3，且不碰 vrFullPath。

**D-2（A2 首页行为未定义）**：小红书首页（explore 列表）没有 `currentNoteId` 对应的单篇 state——`vrFetchXhsNoteInfo` 的 URL 正则已挡掉非详情页（resolve(null) 静默回退），行为是安全的，但方案文档必须写明：**首页仍回退页面标题命名（维持现状），按笔记分组命名是 A4 独立任务**。上一轮方案没写这条边界。

**D-3（A3 不彻底）**：默认档改 0 后，用户能看到 70 张网格、能勾选——「没得选」部分解决。但 `tierCounts` 的 unknown 计数没有对应按钮（TIERS 无 unknown key），70 张未知图只能混在「全部」档看，**无法单独筛出**。彻底解法有两个：① UI 加「未知」档按钮；② 点卡片触发解码回填真实尺寸。建议本批只做 ①（低成本），② 列入 BACKLOG。

**D-4（验证边界必须诚实）**：9480 实例今日配额 6/6 已用完。A1/A2/A3 本批只能完成：Node 单测（档位语义）+ 隔离实例本地 fixture（state 取数链路）。**真实小红书页验证必须明天补跑**，不跑不算关闭——方案里要写进 P1 出口门禁，不能像上轮一样「代码完成≈完成」。

**D-5（术语撞车）**：ADR-071 与 EXECUTION-PLAN 验收条款里的「A2」指 TEST-ASSETS 素材 A2（小红书详情页），本方案任务也叫 A2——**实施文档必须换编号**（建议 M-1 tabId 修复 / M-2 权威命名 / M-3 档位 / M-4 分组 / M-5 原图域名增量），否则验收记录会张冠李戴。
