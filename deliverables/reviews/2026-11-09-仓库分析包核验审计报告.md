## 0. 不支持 Firefox

**本产品不支持 Firefox。** 这不是推断，是本次核验确认的既成事实，也是后续所有结论的前提：

- `manifest.firefox.json` 被 `tools/build-dist.js:57` 的 `/^manifest\.firefox\.json$/i` **明确排除在发布包之外**，`dist/` 里不存在该文件；
- 该清单 `background.scripts` 只有 5 个文件（polyfill / function / templates / init / background），`content_scripts` 只有 1 组；而资源库、去重、站名、路径、索引等能力全靠 `background.js` 里的 `importScripts()` 加载——在非 Service Worker 的后台页环境里这个 API 不存在；
- `browser_specific_settings.gecko.id` 仍是上游作者邮箱 `xifangczy@gmail.com`，版本 `2.7.2` 与 Chrome 清单的 `2.7.2.1` 不同步；
- `README.md` 中 `Firefox` 出现 **0 次**；`docs/INVENTORY-2026-11-06.md:289` 明确写「项目只面向 Chrome/Edge」。

因此报告 `B3` 的方向性结论成立（"要么真正支持、要么明确声明放弃"），但**产品侧尚未把这句结论正式落到 README 与清单治理里**，这是修复文档 T2 要办的事。报告的 `B3` 技术表述则有误：Firefox 清单是 **MV3**（`manifest_version: 3`），不是 MV2；`background.js` 第 3 行注释也自相矛盾地写着「firefox 使用 v2」。

## 6. 总体判断

**这是一份"代码层很扎实、结论层不可直接采纳"的审查报告。**

- **可信的部分**：静态审读质量高。42 条声明里 21 条完全正确，行号级引用（B2/B5/B6/B7/U1/A3/V1/V3/V4）几乎逐行命中，25 个测试套件、构建产物、清单校验这些可复现结论也都对得上。它诚实标注了证据等级与 8 类未验证项，没有把推断伪装成实测。
- **不可采纳的部分**：唯一的 P0（B1）**归因与修复方向错误**，且与仓库内已有的 ADR/QA 证据直接冲突；10 条"部分正确"里有一半是**信息过时**（把已完成的修复写成待办）；5 条错误里有 3 条是**文档数字腐烂**被报告原样引用。
- **根因**：审查者读了代码，但**没读仓库自己的决策记录**。审计产物也没有把结论结构化、绑定 commit、绑定可复跑的检查，导致三个月后同一份报告无法自证。
- **结论**：**不按报告第 5 节的执行顺序开工**。先按修复文档 R 系列修订报告（尤其 B1），把"不支持 Firefox"正式落地，再按 P 系列处理产品真实缺陷；浏览器运行态的 6 条声明单独列入实机复测清单，不并入已关闭项。
