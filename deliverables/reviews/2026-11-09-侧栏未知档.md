# 侧边栏「未知尺寸」独立档（B-68）

> 2026-11-09 · 苏哥报「未知尺寸应该单独列个选项筛选吧？为啥要和其他一起混着」
> 位置：图片嗅探侧边栏（`image.html`）的尺寸档位行

---

## 一、原来为什么混着

档位只有「全部 / 小 / 中 / 大 / 超大」五个，而**尺寸未知的图不参与尺寸过滤**：

```js
if (it.w > 0 && it.h > 0 && shortSide(it.w, it.h) < tierMin) { return false; }
```

这条规则的初衷是好的（懒加载站点上大量 `<img>` 还没解码，按尺寸筛会把整页图吞掉），
但副作用就是苏哥截图里那样：**选中「大 ≥1200」却还显示一堆「尺寸未知」**，
看着像筛选没生效；而这些图又没有任何入口能单独挑出来。

## 二、改法

| 档位 | 语义 |
|---|---|
| 全部 | 什么都要（含未知）—— 保持原样，避免「整页图被吞」 |
| 小 / 中 / 大 / 超大 | **只要该档**；尺寸未知的不再混进来 |
| **未知**（新增） | 只要尺寸未知的：懒加载没解码、背景图、只有源码地址的 |

- 「未知」按钮用**虚线边框**，和四个尺寸档区分；选中后转实线（同其它档选中态）
- 计数独立：`全部 392 / 小 68 / 中 20 / 大 1 / 超大 0 / 未知 324`（真机实测）
- 选中「未知」时档位行补一句小字：**「多半是图标/头像/占位图，建议挑着下」** ——
  这批图默认也会被全选（与其它档一致），不说明白容易一键下几百张废图
- 档位值用 `-1` 表示「未知」，能存能读（`vrLibSettings.imgTierMin`）：
  早先只认 `>= 0`，切到「未知」后重开侧边栏会静默退回「全部」
- 新增自愈提示：本页一张都没量出尺寸时，不再硬切回「全部」，
  改为底部提示「点『未知』可以单独看」
