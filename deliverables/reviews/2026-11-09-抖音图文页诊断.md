# 抖音图文页（/note/&lt;id&gt;）图片下载失效 · 诊断与修复

> 日期：2026-11-09 ｜ 报告人：吴八哥 ｜ 触发：苏哥报「抖音图文页没有图片下载按钮、点扩展嗅探不到本页内容、页面上有个超大按钮被隐藏」
> 样本：https://www.douyin.com/note/7705250862063743461 （摄影师沙皮 · 舞蹈少女，15 张图）
> 取证方式：CDP 直驱 9480 实例（真实登录态）+ 页面 DOM / React Fiber / SW 嗅探缓存三路取证

---

## 一、结论先行

| 苏哥看到的现象 | 真正的原因 | 性质 |
|---|---|---|
| 页面上**没有图片下载按钮** | 抖音图文的作品图**不是 `<img>`**，是轮播每一页那个 1369×876 透明 `<button>` 的 `background-image`。悬停按钮只绑 `<img>` → 永远不触发；右下角批量浮标按 2026-10-25 产品决策**默认关闭**（`imgPanel:false`）→ 页面零入口 | 通用通道能力缺口 + 既有产品口径 |
| 点扩展后**嗅探不到本页内容** | 侧边栏扫描把「尺寸档位」当成了**采集门槛**：浏览器里存着 `imgTierMin=2000`（之前点过「超大」档），下次扫描拿 2000 去 `scanImages` → 1066×1424 的作品图整批被筛掉，列表只剩源码正则抓来的 297 条无尺寸地址，全都显示「尺寸未知」 | 真 bug（采集/筛选职责混用） |
| 页面里有个**超大按钮被隐藏** | 不是我们的元素：抖音图文轮播每页就是一个 1369×876 的透明 `<button class="QAUHVhVM">`，10+ 个并排（x=165 / 1534 / 2903 …）。它盖在照片上，既解释了「隐形大按钮」，也解释了为什么点图不会触发我们的悬停按钮 | 站点结构（如实说明，不修） |

**一句话**：抖音图文把照片渲染成「轮播按钮的背景图」，而我们的图片入口只认 `<img>`；同时侧边栏又拿档位当采集门槛，把真图筛干净了。两头一夹，就成了「没按钮 + 没内容」。

## 二、现场取证（2026-11-09，9480 实例）

### 2.1 页面结构

```
imgTotal 125 / naturalWidth>=1000 的 32 张
noteImgs（aweme-images）: 1066×1424 / 1066×1600，显示尺寸 620×828 与 1369×876 各一份
bgCount（大面积 background-image）: 0  ← 背景图挂在 slide <button> 上，尺寸=容器
bigButtons: 10 个 <button class="QAUHVhVM"> 1369×876 @x=165,1534,2903,…
videos: 2 个（其中一个 1526×0 的预加载隐形节点）
```

### 2.2 嗅探白名单（SW 侧 `G.Ext` / `G.Type`）

```
ext(32): flv hlv f4v mp4 mp3 wma wav m4a ts webm ogg ogv … mpd weba opus srt vtt
type(9): audio/* video/* application/ogg application/vnd.apple.mpegurl … application/dash+xml
→ 没有任何图片扩展名，也没有 image/*
```

**结论**：`popup` 的「嗅探列表」本来就不收图片（图片能力在侧边栏），所以「点扩展看不到图」一半是产品口径、一半是侧边栏列表被门槛筛空。本次不动白名单，避免和「图片走侧边栏」的既有结构打架（见 §六 遗留 1）。

### 2.3 Fiber 里的真身（`awemeInfo.images[]`，15 条）

```
awemeId 7705250862063743461  desc 舞蹈少女。…  authorInfo.nickname 摄影师沙皮
images[0] = { width:1066, height:1424, uri:"tos-cn-i-0813c000-ce/oMqd…",
              urlList:[ …:q75.webp, …:q75.webp(p9), …:q75.jpeg ],      ← 无水印，可用
              downloadUrlList:[ …dy-water-v2:… ] }                     ← 带水印，弃用
```

实测三种地址：

| 地址 | 结果 |
|---|---|
| `…~tplv-dy-aweme-images:q75.webp`（带签名） | 200 · image/webp · 39KB |
| `…~tplv-dy-aweme-images:q75.jpeg`（各自签名） | 200 · image/jpeg |
| 去掉 `~tplv-` 后缀（想拿原图） | **403** —— 签名覆盖路径，去后缀这条路不通 |

**所以「无水印最高清」= `urlList` 里的 jpeg/webp 档（1066×1424），不是「原图」**。这点必须如实写在按钮提示里，不能让用户以为下到了原始分辨率。

### 2.4 侧边栏扫描口径（修复前）

`js/image-page.js` 的 `scanInPage({ minSize: tierMin > 0 ? tierMin : 1 })`：档位 2000 → `scanImages` 门槛 2000 → 真图（短边 1066）全灭；`srcScan` 抓到的地址 `w=0/h=0`，`visibleItems()` 对未知尺寸**不按档位过滤** → 列表里全是它们 → 「297 张，全部尺寸未知」。

同处还有第二个 bug：点「全部」档 `parseInt('0') || 100` 会变成 100，把「全部」偷偷变成 100 门槛。

## 三、竞品对照（星愿浏览器里已装的两个同类）

| 扩展 | 取图方式 | 对我们的结论 |
|---|---|---|
| **智小抖 v2.4.5**（`lpnhhgnafkmcomhoabfaiblbeajfncde`） | 爬 React Fiber：从播放器/卡片 DOM 找 `__reactFiber$*`，读 `props.awemeInfo`；驼峰字段（`awemeId`/`authorInfo`/`urlList`），**不调接口、不碰签名**。我们 2026-11-09 已按它改造了视频链路（`js/douyin.js: playerFunc`） | ✅ **同一条路复用**：图文新增 `noteFunc`，读 `awemeInfo.images[]`。图文的图和视频的流在同一个 awemeInfo 里，没必要再发明第二种取法 |
| **图片下载器 4.0.0**（`flbolonkboilcbnohjlchlfgdalomdpl`） | `<img>` + `srcset` + computed `background-image` + `body.innerHTML` 正则；每张图套 wrapper 挂悬浮钮 | ✅ 背景图扫描与源码正则我们已有（§8.3，已抄）；❌ 每图套 wrapper 不抄（长页面糊满屏，已定论） |

**关键差异（也是我们这次补的）**：竞品都把「取图」和「入口」绑在一起——智小抖在抖音页给按钮，图片下载器在图上挂钮。我们此前把图片能力全收进侧边栏，页面上就真的一个入口都没有；而抖音图文的图恰好是 `<img>` 摸不到的形态，于是侧边栏成了唯一出口，出口又被档位堵住。

## 四、修复清单

| # | 文件 | 改动 | 为什么 |
|---|---|---|---|
| 1 | `js/image-page.js` | 扫描门槛恒为 `minSize: 1`；档位只做 `visibleItems()` 显示筛选 | 采集与筛选职责分离。档位是「我想看多大的」，不是「本页有没有图」 |
| 2 | `js/image-page.js` | 点「全部」档 `parseInt(...) \|\| 100` → 显式判 NaN（得到 0） | 「全部」被偷偷变成 100 门槛，用户永远回不到「全部」 |
| 3 | `js/image-page.js` | 档位自愈：本页有尺寸图被当前档位筛光时，自动切回「全部」并在底部提示 | 历史存的 2000 档会让人以为「没嗅探到」，自愈一次就再也不会踩 |
| 4 | `js/douyin.js` | 新增 `noteFunc()`（主世界执行）：从 Fiber 收 8 条候选 awemeInfo → 按 URL 里的作品 ID 选中当前这条 → 读 `images[]`，主地址优先 jpeg，webp 与其它镜像作候选链 | 图文的图只在 Fiber 里；`world:'MAIN'` 才能摸到 React expando |
| 5 | `js/background.js` | 新增 `vrDouyinImages` 消息 + `vrDouyinImages()`：`executeScript({world:'MAIN', func: VR_DOUYIN.noteFunc})`，6s 超时，返回 `{awemeId,title,nickname,uniqueId,images[]}` | 内容脚本在隔离世界看不到 Fiber，必须借 SW 注入主世界 |
| 6 | `js/douyin-note.js`（新） | 抖音图文页浮层按钮：`⤓ 下载本作品图片 15`，固定在画面左上角（视频浮层占右上角，避开）；点击走 `VRImgBridge.download`，标题 `作品标题_01…`；SPA 路由变化、首屏慢渲染都有兜底（1s 盯路径 + 最多 4 次退避重试） | 页面上必须有一个看得见、点得到的入口（ADR-047：通用优先，专站增强体验） |
| 7 | `js/image-batch.js` | `vrImg.batch` 消息增加可选 `authorFull` / `creatorId` | 归档能落到 `<平台>/<作者>/`，不再是 `抖音/www.douyin.com/<标题>/` |
| 8 | `js/background.js` | `vrImgBatch` 把消息里的 `authorFull/creatorId` 透传给 `vrImgDownload`（小红书仍是 state 覆盖优先） | 同上 |
| 9 | `manifest.json` | 新增 content script：`*://www.douyin.com/*` → `js/douyin-note.js`（document_idle，追加在图片栈之后，确保 `VRImgBridge` 已就绪） | 注册入口 |

**没做的事（有意）**：不改嗅探白名单加 `image/*`；不改浮标默认值；不给每张背景图套悬浮钮。理由见 §六。
