## 一、结论先行

智小抖取抖音标题/作者/清晰度，**不靠 DOM 选择器、不靠主动调接口、不碰签名**。它用两条路：

| 路线 | 做法 | 我们的可借鉴度 |
|---|---|---|
| **路线① React Fiber 抠播放器** | 从 `<video>` 往上找带 `__reactFiber$*` 的祖先节点，爬 Fiber 树读 `props.awemeInfo`，直接拿到**当前正在播这条视频**的完整数据对象 | ★★★★★ 核心，解决首页/精选/搜索/主页全场景 |
| **路线② 拦截页面自身请求** | MAIN world hook `window.fetch` + `XMLHttpRequest`，比对 30 个接口清单，把页面**自己已经请求到**的响应 `postMessage` 回扩展 | ★★★★☆ 补充，覆盖批量列表场景 |

**关键事实：它全仓库 0 次出现 `a_bogus` / `X-Bogus` / `msToken` / `verifyFp`。** 它从不自己发请求，所以永远不需要签名。

## 二、路线① 实现细节（`extractAwemeInfoFromPlayer`）

反编译后的等价代码（源：`dyIndex.f0551f34.js` @3090839，模块 `~utils/dy/reactAwemeInfo`）：

```js
function pick(arr) {                       // 从 React children 里找 awemeInfo
  for (const c of (Array.isArray(arr) ? arr : [arr])) {
    const info = c && c.props && c.props.awemeInfo;
    if (info && (info.awemeId || info.aweme_id)) return info;
  }
  return null;
}
function extractAwemeInfoFromPlayer(el) {
  const key = Object.keys(el).find(k => k.startsWith('__reactFiber$'));
  if (!key) return null;
  const fiber = el[key];
  const tries = [
    () => fiber.child?.memoizedProps?.itemInfo,          // 卡片列表形态
    () => pick(fiber.child?.memoizedProps?.children),    // 子层 children
    () => { let e = fiber.memoizedProps?.children;
            if (Array.isArray(e)) e = e.find(x => x?.props?.children);
            return pick(e?.props?.children); },
    () => pick(fiber.memoizedProps?.children),
  ];
  for (const t of tries) { try { const r = t(); if (r?.awemeId || r?.aweme_id) return r; } catch (e) {} }
  return null;
}
```

调用方式：拿播放器容器 DOM 元素传进去（`getVideoInfo(el){ return extractAwemeInfoFromPlayer(el) }`）。

## 三、路线② 接口拦截清单（`inject.6070000c.js`）

```js
injectFetch() {
  const orig = window.fetch;
  window.fetch = async (...a) => {
    const resp = await orig(...a);
    resp.clone().text().then(text => this.match(a, resp.url, text)).catch(()=>{});
    return resp;                       // 不改响应，纯旁路监听
  };
}
injectXhr() {
  XHR.open = function(m,u){ this._method=m; this._url=u; return orig.apply(this,arguments); };
  XHR.send = function(body){
    this.addEventListener('readystatechange', function(){
      if (this.readyState===4 && this.status===200) match(body, this._url, this.response);
    });
    return origSend.apply(this,arguments);
  };
}
match(reqArgs, url, text) {
  for (const api of new ApiMap().getApiMap()) if (url.indexOf(api.url) > -1) {
    postMessage({ type:'inject-data', content:{
      api_url:url, dp_code:api.dp_code,
      iden_key: api.iden_key({url}),        // 从 URL query 取主键（aweme_id/sec_user_id/keyword）
      api_name: api.api_name,
      resp_data: JSON.parse(text) }}, '*');
    break;
  }
}
```

## 四、对照我们自己的实现：为什么我们首页拿不到标题

我们现在的链路（`js/douyin.js` + `js/background.js:4774`）：

```
vrVideoOptions(tabId)
  └─ parseAwemeId(tab.url)      ← 只认 /video/<id> 与 ?modal_id=<id>
     └─ 有 ID → MAIN world fetch 详情接口 → metaFrom → 标题=desc ✅
     └─ 无 ID → 直接掉进通用嗅探分支 ❌ 抖音接口根本没被调用
```

**实机取证（2026-11-09，Edge 登录态）**：抖音精选页 URL 是 `https://www.douyin.com/jingxuan`，**不含任何作品 ID** → `parseAwemeId` 返回空 → 走通用嗅探 → 拿到的是推荐位/预加载视频，元数据全靠 `naming.js` 的 DOM 提取。

而 `naming.js:extractDouyin` 的两个锚点在新版抖音**全部不存在**：

```js
// 我们现在的写法
post = textOf(q(doc,'[data-e2e="detail-video-info"] h1'))   // ← 精选页无此节点
author = attrOf(q(doc,'[data-e2e="user-info"] img[alt]'),'alt')  // ← 精选页无此属性
```

实测精选页 `data-e2e` 只有：`douyin-navigation / searchbar-input / im-entry / live-avatar / conversation-item / alink-item`——**一个内容锚点都没有**。

结果：`title` 空 → 兜底 `document.title`（"抖音精选电脑版 - 抖音旗下优质视频平台"）→ 模板 `${author}_${title}` 填空 → **文件名只剩一段，苏哥看到的"只有作者名没有标题"就是这么来的**。

更讽刺的一点：精选页卡片里 `img.discover-video-card-img` 的 **alt 装的是标题**，而我们代码里把 `img[alt]` 当**作者**取——方向正好反了。

## 五、施工结论（按优先级）

1. **P0｜加路线①**：`js/douyin.js` 新增 `playerFunc`（MAIN world 自包含函数，爬 Fiber 抠 `awemeInfo`），`vrVideoOptions` 抖音分支改为**先试 Fiber、拿不到再试 URL+详情接口**。一次覆盖首页/精选/搜索/主页全部场景。
2. **P0｜归一化**：Fiber 是驼峰、接口是下划线，`normalize`/`metaFrom` 两套 key 都要认；`playAddr` 是 `[{src}]` 数组不是 `[url]`。
3. **P1｜修 `extractDouyin`**：`img[alt]` 当标题（不是作者）；作者改从 `a[href*="/user/"]` 文本取；`document.title` 兜底加「抖音精选电脑版」这类**站点宣传语黑名单**，别当标题用。
4. **P2｜可选路线②**：真要覆盖主页批量/收藏夹/历史，照抄 fetch/XHR 旁路监听 + `postMessage` 回传。但注意这是**新增常驻注入**，与我们「只改壳不改内核」原则要权衡——建议等 P0 实测后再定。
