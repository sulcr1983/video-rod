## 一、苏哥问的是什么

「刚在媒体库删微博这条，删不掉，回收站也没有。是以前的问题吗，还是现在还有？」

**先给结论：不是上次那个已修好的「清空回收站后索引复活」，是另一处、今天仍在发生的缺陷。**
上次（2026-11-10 凌晨）修的是「文件删了、索引/缩略图没删」；这次是**文件压根没删动**，所以回收站当然是空的，卡片当然还在。

## 二、现场取证（只读，没动任何用户素材）

| 证据 | 结果 |
|---|---|
| 操作日志 | `_migration/ops-20261110-122625-dofm.json`（12:26，苏哥提问前一分钟）：`action=delete`、`moved=[]`、`cleaned=0`、**`failed=[1]`** |
| 失败详情 | `relPath = video-rod/微博/地球知识局(@5750600479)/视频/…区… (1).mp4`、`code=11`、`message = "An operation that depends on state cached in an interface object was made but the state had changed since it was read from disk."`（FSA `InvalidStateError`） |
| 回收站 | `VRTrash.status()` = 0 项 / 0 批；磁盘 `_回收站/` 空 |
| 索引 | 真实 IDB 50 行**全部 `state=ok`**（失败后打标已回滚，没有制造死卡） |
| 磁盘 | `…区… (1).mp4` 与 `…区….mp4` 两份都在，各 119235952 字节（= 截图里两张 113.7 MB 卡）；路径最长 126 字符，未超 Windows 限制 |
| 句柄体检 | `queryPermission(readwrite)=granted`；`微博 / 地球知识局(@…) / 视频` 三级目录句柄逐级获取全 ok；`getFile()` 成功，文件可读 |

**结论 A**：不是权限、不是文件名非法、不是路径超长、不是文件丢失。文件好端端在盘上，是浏览器 File System Access 的**句柄状态缓存与磁盘临时对不上**（Windows 上偶发），一次搬文件调用被 `InvalidStateError` 挡下；旧代码没有重试，按设计回滚打标 → 卡片留在主页、回收站 0 项。

**结论 B（另一半问题）**：`VRTrash.remove()` 失败不抛异常，结果放在 `rr.failed` 里。单条删除的三个 UI 入口（键盘 Delete / 查看器删除 / 右键「移到回收站」）**都没看这个字段**，一律弹「已移入回收站」。所以苏哥看到的是「提示说删了，实际没删，回收站也找不到」——最误导人的一种假成功。
