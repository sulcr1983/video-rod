## 零、播放器格式兼容（实测结果）

> 用 Chrome 156 隔离实例跑 `canPlayType` 实测（探针 `tools/cdp-subtitle-fmt-probe.py`），逐格式探测。

### 0.1 结论一句话

**本地播放器 = 裸 `<video>` + Plyr，没接任何解码库。所以「能放什么」完全取决于 Chrome 原生支持什么。好消息是：咱们下载下来的视频，落盘时基本都合并成 mp4/webm 了，所以「自己下的」几乎全兼容；只有从别处拷来的 flv/ts/avi 才放不了。**

### 0.2 实测明细

| 格式 | canPlayType | 结论 |
|---|---|---|
| mp4 H.264+AAC（B站/抖音/小红书/微博主流） | probably | ✅ 稳 |
| mp4 HEVC/H.265 | probably | ✅ 稳 |
| mp4 AV1 | probably | ✅ 稳 |
| webm VP8/VP9/AV1 | probably | ✅ 稳 |
| mkv（H.264 容器） | maybe | ⚠️ 多数能放，但带字幕轨/DTS 音轨的不保证 |
| mov / m4v | maybe/空 | ⚠️ H.264 的常能放，不算稳 |
| ogg / 3gp | maybe | ⚠️ 老格式，能放但少用 |
| **flv**（B站 durl 旧格式） | 空 | ❌ 放不了 |
| **ts**（m3u8 分片） | 空 | ❌ 放不了 |
| **avi** | 空 | ❌ 放不了 |
| m3u8 / mpd | maybe（**假象**） | ❌ 裸 `<video>` 放不了，需 hls.js/dash.js |

### 0.3 两个必须知道的坑

1. **m3u8/mpd 的 `canPlayType` 返回 `maybe` 是假象**：浏览器声称「可能」支持，但把 `.m3u8` 直接塞给 `<video src>` 是**播不了的**——它需要 hls.js / dash.js 接管。**但咱们下载管线（m3u8 合并 MP4、B站 DASH 合成、YouTube fmp4 合并）在落盘前就已经合成 mp4 了**，所以本地库里基本碰不到裸 m3u8。这就是为什么播放器不接 hls.js 也一直没出事。
2. **flv/ts/avi 放不了**：如果苏哥有从别处拷进来的这类文件，需要一个「转封装」或「转码」兜底（ffmpeg.wasm 前端转封装，或提示用别的播放器），这是另一个独立需求，跟字幕无关，先记着。

### 0.4 要不要补解码能力？

- **不需要**：自己下载的视频 99% 是 mp4/webm，已全兼容。
- **可选（低优先）**：接 `hls.js` 就能直接放 m3u8 直链（不合并）；接 `dash.js` 放 mpd。但跟「落盘已合成 mp4」的现实冲突，收益很小。
- **可选（低优先）**：`ffmpeg.wasm` 前端转封装 flv/ts→mp4。重（wasm 约 30MB），只为「外来文件」兜底，性价比低，先不做。

## 一、结论（先说人话）

**一句话：外挂字幕能做，而且轻、快、不用本地部署；「实时字幕」这事 Chrome 已经免费给你了，但产品里内置 ASR（语音识别）这版不做，因为那就是你之前踩过的「又慢又大又卡」的坑。**

三件事分清楚：

| 你要的 | 是什么 | 能不能做 | 代价 |
|---|---|---|---|
| **外挂字幕**（.srt/.ass 字幕文件挂到视频上） | 播放时把现成字幕文件显示出来 | ✅ 能做，推荐做 | 轻，几十行代码，无重依赖 |
| **实时字幕**（没字幕文件，靠 AI 听音频现生成） | 语音识别（ASR）转文字 | ⚠️ 分两种，见下 | 视路线 |
| **Chrome 自带实时字幕** | 浏览器内置的语音转字幕 | ✅ 现在就能用 | 零成本，但浮窗归 Chrome 管 |

### 关于「实时字幕」，两句话拆开讲

1. **Chrome 自带的「实时字幕」现在就能用**：设置 → 无障碍 → 实时字幕，打开后，**任何在浏览器里播放的视频/音频**（包括咱们本地播放器里播的视频）都会浮出一行实时生成的字幕，支持中文（简体/繁体），**完全离线运行、不用装任何东西**。缺点是：字幕浮窗是 Chrome 的，位置/样式归它管，我们产品控制不了它；准确率「够看懂大意、不能当精准字幕」，且**不能导出保存**。适合当「免费兜底」。

2. **产品里内置 ASR（本地语音识别）这版不做**：你之前试的「要本地部署、又慢又大又卡」就是这类——Whisper 模型跑本地，要么在浏览器里跑 WASM（模型几十 MB~几百 MB，CPU 慢），要么起本地服务（重）。这是**真正的又慢又大又卡**，违背咱们「通用优先、轻量」的铁律。**这版明确不做**，除非哪天有刚需再单独立项评估。

## 二、外挂字幕：可行，且已实测验证

### 2.1 现状（项目里已经具备的地基）

- 本地播放器用的是 **Plyr**（`lib/plyr/plyr.min.js`），一个成熟的开源播放器，**原生就支持字幕**（走浏览器 `textTracks` 机制）。
- 播放器代码在 `js/library/lightbox.js`（`renderStage` 里 `kind === 'video'` 分支，创建 `<video>` + 初始化 Plyr）。

### 2.2 关键实测（本轮已跑通，不是纸上谈兵）

我用隔离浏览器实机验证了**字幕能不能在 Plyr 里显示出来**，结果：

| 验证项 | 结果 |
|---|---|
| 程序化注入字幕轨道 `addTextTrack('subtitles','中文','zh')` + `VTTCue` | ✅ 成功，2 条 cue 全注入 |
| Plyr 把字幕画到屏幕上（`.plyr__captions`） | ✅ 中文显示正常：「第一条 外挂字幕 中文测试」 |
| Plyr 字幕相关 API（`currentTrack` / `captions`） | ✅ 可用，自定义按钮有接口 |
| 换行/多 cue | ✅ 正常 |

**结论：字幕显示这条路，技术上是通的，不依赖任何新库。**

### 2.3 一个必须知道的坑（决定实现方式）

扩展页面（`chrome-extension://` 里打开的本地播放器）**不能直接 `fetch('file://...')` 读字幕文件**，也被 Chrome 的 URL 安全策略拦。这是实测确认的（跟项目里 `app.js` 第 3678 行注释「扩展页读 file:// 受限」是同一个坑）。

所以字幕文件**不能靠 `<track src="file://...">` 直接加载**，而是两条路：

1. **File System Access 句柄读**：项目已经有 `js/library/localfile.js` 的 `VRFile.resolve`，用目录句柄逐段找文件。字幕文件跟视频放同一个目录，就能用同一套句柄读出来 → 转成文本 → 程序化注入。**零新依赖，这是首选路。**
2. **手动选字幕文件**：播放器里加一个「挂字幕」按钮，点一下弹系统文件选择框选 `.srt` 文件读内容。兜底方案，永远可用。

两条路**都做**最稳：自动找同目录同名字幕（省事），找不到再手动选（兜底）。

## 三、开源方案盘点（按铁律先搜后写）

| 需求 | 候选 | 许可证 | 活跃度 | 结论 |
|---|---|---|---|---|
| SRT 解析 | `srt-parser-2`（npm） | MIT | 一般（但稳定） | 可选；也可自写 30 行（SRT 格式极简） |
| ASS/SSA 特效渲染 | `JASSUB`（libass 的 WASM 版） | MIT | ✅ 活跃（2026-01 还在更新） | **ASS 特效字幕的权威方案**，但需开 wasm，重 |
| ASS 解析（纯文本提取） | `ass-compiler` / `sweet-subtitle` | MIT | 中 | 只取台词不要特效时可选 |
| 字幕渲染器替代品 | `SubtitlesOctopus`（libass WASM） | 较老 | 维护慢 | 被 JASSUB 取代，不推荐 |

### 我给的选型建议（分阶段，不一次吃成胖子）

| 阶段 | 做什么 | 依赖 | 说明 |
|---|---|---|---|
| **第一版（推荐现在做）** | 外挂 **SRT / VTT** 字幕：自动找同目录同名 + 手动选文件 | **零新依赖**（自写 ~30 行 SRT→cue 解析） | 覆盖绝大多数场景，轻、快、无风险 |
| **第二版（可选，等反馈）** | 外挂 **ASS 字幕**（动画特效字幕，动漫党常用） | `JASSUB`（需 manifest 开 `wasm-unsafe-eval`） | 重，但 ASS 特效只有它能真渲染；先问苏哥有没有这需求 |
| 不做（本期） | 内置 ASR 实时字幕 | — | 就是你踩过的「又慢又大又卡」，不做 |

## 五、字幕从哪来：API 在线字幕 + 没字幕的视频加字幕（追加需求）

苏哥澄清：字幕不只是「外挂现成文件」，还想知道两件事——**有没有字幕 API 能自动拉**，以及**没字幕的小视频能不能自动加字幕**。分开讲。

### 5.1 字幕 API（在线字幕源）：有，但跟咱们的场景不太对得上

| 字幕源 | 语种 | 匹配方式 | 费用 | 对咱们的价值 |
|---|---|---|---|---|
| **OpenSubtitles.com API** | 国际（中/英/日…） | 片名 / IMDb / TMDB / **文件哈希** | 免费（有额度） | 影视剧长视频有用；**短视频搜不到** |
| **assrt.net（人人字幕）** | 中文 | 片名 / IMDb | 免费（需 token） | 影视剧、日剧动漫有用；短视频没有 |
| **射手网 shooter.cn** | 中文 | 片名 | — | **已关站**，不可用 |
| **Jimaku** | 日文动画 | 片名 | 需 key | 动漫党专用 |

**诚实结论：字幕 API 对咱们的核心场景（B站纪录片分P、抖音/小红书短视频、微博推特存图）帮助有限。** 原因很直白——这些 API 是给「电影/剧集」建的，靠 IMDb/片名匹配；而短视频没有 IMDb 条目，也没人去给短视频建公共字幕库。唯一可能命中的是：如果苏哥下载的是**影视剧/动漫/纪录片**，用 OpenSubtitles 按片名能拉到。所以：

- **字幕 API 可以做，但定位是「锦上添花的备胎」**：播放器里加一个「搜索在线字幕」按钮，对**长视频**按文件名/片名去 OpenSubtitles 搜，命中就下载挂上。短视频点了也搜不到，不会有害，但别指望它。
- **关键坑**：OpenSubtitles 需要注册拿 API key；按「文件哈希」精确匹配最准，但那要求先算视频的哈希（大文件要读一遍）。

### 5.2 没字幕的视频加字幕（ASR）：这才是苏哥要的「更美」

苏哥说「很多小视频没字幕，加入字幕估计更美」——这是**自动语音转字幕（ASR）**，跟「外挂现成文件」是两回事。方案分两档：

| 方案 | 原理 | 快慢 | 成本 | 结论 |
|---|---|---|---|---|
| **云 ASR API**（推荐） | 抽音频 → 传云端识别 → 拿带时间戳文字 → 生成 SRT | 快（分钟级） | 按分钟付费，约 **0.4~2.4 元/分钟**（讯飞/阿里/腾讯/火山豆包/OpenAI Whisper 都这量级） | ✅ 快、准、零本地负担，但要联网 + 申请 key + 付钱 |
| **本地 Whisper**（不推荐） | 浏览器里跑 whisper WASM | 慢 | 零钱但耗 CPU/内存 | ❌ 就是你踩过的「又慢又大又卡」坑 |
| **Chrome 自带实时字幕** | 浏览器内置 | 即时 | 零 | ✅ 免费，但浮窗归 Chrome、**不能导出成文件** |

**我的判断（专家建议）**：

1. **「小视频自动加字幕」这事，技术上要做就做「云 ASR 按需生成」**——播放器里加个「生成字幕」按钮，点一下：抽音频 → 调云 ASR → 生成同名 `.srt` 存到视频旁边 → 自动挂上。**按需触发，不是下载时全自动跑**（否则每条视频都花钱+耗时，太烧）。
2. **但它有三个前置门槛，得苏哥先认账**：
   - **要申请一个云 ASR 的 key**（讯飞 / 阿里云 / 腾讯云 / 火山引擎豆包，中文识别都强），并把 key 存进扩展设置。
   - **要联网 + 按分钟付费**（0.4~2.4 元/分钟，一分钟视频约几厘到几分钱；长视频会累积）。
   - **音频要上传云端**（隐私考量：你下载的视频音频会传到第三方服务器转写）。
3. **性价比提醒**：如果只是「看着更美」，最省事的其实是 Chrome 自带的实时字幕（零成本零配置），但它不能存成文件。云 ASR 是「真给你生成一个字幕文件」的正解，代价是 key + 联网 + 钱 + 上传音频。

### 5.3 合并后的完整字幕能力地图

| 能力 | 做什么 | 依赖 | 建议 |
|---|---|---|---|
| ① 外挂现成字幕（SRT/VTT） | 同目录同名自动挂 + 手动选文件 | 零依赖 | **第一版就做** |
| ② 在线字幕搜索（OpenSubtitles） | 长视频按片名/哈希拉字幕 | API key | 第二版，锦上添花，短视频指望不上 |
| ③ 云 ASR 自动加字幕 | 没字幕的视频现生成 SRT | 云 key + 付费 + 联网 | 苏哥拍板要不要；要就按需触发 |
| ④ ASS 特效字幕渲染 | 动漫特效字幕 | JASSUB（重） | 看苏哥有没有 ASS 需求 |
| ⑤ Chrome 自带实时字幕 | 免费兜底 | 无 | 现在就能用，不可导出 |

## 七、给苏哥的一句话总结

三个问题一次说清：**①播放器兼容性**——自己下载的视频落盘时都合成 mp4/webm 了，Chrome 原生全放得了（实测过），只有从别处拷来的 flv/ts/avi 放不了，这个坑先记着不用补。**②字幕 API**——有（OpenSubtitles/人人），但它们是给电影剧集建的，短视频搜不到，只能当长视频的备胎。**③没字幕的小视频自动加字幕**——正解是「云 ASR 按需生成」，点一下按钮现生成一个 SRT 存旁边，快而准；代价是要申请个云 key、联网、按分钟付几厘到几分钱、音频要传云端。要轻省就先靠 Chrome 自带实时字幕顶着（免费但不能存文件）。你拍板：外挂字幕第一版做不做、云 ASR 要不要上。
