# 站点名显示成域名 · 诊断报告

- **日期**：2026-11-10
- **报障人**：苏哥（截图：资源库左栏「其他站点 14」里有 3 个站显示域名，问「原来设计里有自动获取网站名字，为啥现在都是域名？」）
- **诊断方式**：静态代码盘点 + 离线可重跑探针 + 三个站点首页实抓
- **本轮动作**：**只诊断，没有改任何产品代码**（新增 1 个只读诊断脚本 + 本报告 + 登记表一行）
- **结论**：功能没丢，是「三段链路只接了两段」——自动抓站名的能力是好的，但**资源库页面从来没去读它抓到的结果**，于是左栏只剩写死的预置表；另外带 `www.` 的两个站还叠加了一个「域名没归一、查不到字典」的缺陷。

---

## 一、先说结论（大白话）

| 疑问 | 答案 |
|---|---|
| 是不是自动获取名字的功能没了？ | **没有**。`js/site-name.js` 的提取器、后台 `vrResolveSiteName()` 的落库链路都在，而且拿这三个站的真实首页跑了一遍，**都能自动提取出名字**（一点资讯 / 4k壁纸 / 百变桌面）。 |
| 那为啥还显示域名？ | 自动名字只在**下载那一刻**（页面有 DOM 时）抓，抓到写进 `chrome.storage.local.vrSiteNames`；而**资源库页面从头到尾没有读这份缓存**，左栏只认得写死的 381 条预置表。截图里 6 个有名字的站全部是预置表命中，3 个域名的站都不在预置表里 → 退回原始 `platform` 字符串（就是域名）。 |
| 为啥两个域名还带 `www.`？ | 第二个缺陷：字典里存的是归一后的 `bizhi66.com`，左栏拿 `www.bizhi66.com` 去查，`nameOf()` 不做归一 → 查不到。就算修好上一个问题，这两个仍然显示域名。 |
| 文档里不是写了会自动获取吗？ | ADR-061 确实写了，也如实记了一条限制：「从没在本机打开过、又不在预置表里的站，显示域名」。但那是**设计上的信息上限**，不是这次的全部原因；实际还多压了两处实现缺陷（缓存没读、域名没归一）。 |

> 顺带纠正一下：截图里不是「都是域名」——9 个站点里 6 个是名字、3 个是域名。看起来扎眼的是那 3 个长尾站。

## 三、三层根因（按"谁挡在前面"排序）

| # | 层次 | 具体位置 | 问题 |
|---|---|---|---|
| **BUG-1** | 接线（P0，主因） | `library.html` / `js/library/app.js` `boot()` | 资源库页加载了 `site-name-store.js`，但**全页没有任何一处调用 `VRSiteNameStore.ready()`**。`VRSiteRegistry.buildRows()` 读的是 `ST.snapshot()`（同步内存镜像），未 ready 时返回 `null` → **自动学习层整体缺席**，索引里只剩预置表。全仓 `ready()` 只有 4 处：`background.js:1000`（下载链路）和 `settings.js` 三处（**options 设置页**，而 `settings.js` 根本没被 `library.html` 加载）。此外 `VRSiteRegistry.refresh()` 在库页也没有任何调用方，索引一旦建成就不刷新。 |
| **BUG-2** | 反查（P0） | `js/library/site-registry.js:267 nameOf()` | `nameOf(key)` 只做 `index[String(key).toLowerCase()]` 精确查，**不去 `www.`、不做可注册域名归一**。字典/缓存的键是 `bizhi66.com`，库里老条目的 `platform` 是 `www.bizhi66.com` → 永远查空。离线实测连 `nameOf('www.xiaohongshu.com')` 都查不到预置表里的「小红书」，说明这是普遍缺陷，不限于这三个站。连带影响：`app.js siteGroupKey()` 在名字拿不到时按原始字符串分组，`www.xxx` 与 `xxx` 会裂成两个节点。 |
| **限制-3** | 设计（P1，文档已承认） | `docs/DECISIONS.md` ADR-061 第 3 条 | 「站名只在有 DOM 的时刻抓（下载那一刻）」。这三条是**历史条目**（当时还没有站名链路，或没走到它），此后资源库重扫只读文件系统、没有 DOM，**没有任何通道给它们补名字**；设置页虽有「输入域名 → 获取站名并加入」（`vrSiteNameProbe`），但要人工逐个点，而且因为 BUG-1，点完左栏也还是不变。 |

**下载链路是好的，不要动它**：`background.js` 的 `vrResolveSiteName()` 三级回退（消息带 siteName → 注入标签页 → 缓存）与 `ST.learn()` 都在；`VRPath`/`VRSiteRegistry.detect()` 有完整 URL 时会正确归一。问题只发生在「已经入库的条目怎么显示」。

## 四、实测证据（可重跑，不是推断）

### 证据 1：离线探针完整复现截图

`node tools/diagnose-site-name-wiring.js`（用内存版 `chrome.storage` 模拟「以前下载时已学到 3 个站名」）：

```
① 现状：资源库页冷启动，store 未 ready
  snapshot(): null → learned 层完全缺席（只剩预置表）
  [名字] xiaohongshu.com = "小红书"     [名字] bilibili.com = "B站"
  [名字] pixso.cn = "Pixso"            [名字] instagram.com = "Instagram"
  [名字] pixabay.com = "Pixabay"       [名字] v.qq.com = "腾讯视频"
  [域名] yidianzixun.com = ""          [域名] www.bizhi66.com = ""
  [域名] www.baibian365.com = ""       [域名] www.xiaohongshu.com = ""

② 假设修好 ready() + registry.refresh()
  [名字] yidianzixun.com = "一点资讯"  [名字] bizhi66.com = "壁纸66"
  [域名] www.bizhi66.com = ""   ← BUG-2 仍在，带 www 的依旧是域名
  [域名] www.xiaohongshu.com = "" ← 连预置表都查不到

对照组：下载链路 detect()
  https://www.bizhi66.com/a → key=bizhi66.com name="壁纸66"  ← 本来就归一
```

① 的输出与截图**逐项吻合**（6 个名字 / 3 个域名）。

### 证据 2：三个站点首页能自动提取出名字

实抓公开首页（不带 cookie），交给项目自己的 `VRSiteName.parseHtmlInfo()`：

| 站点 | `<title>` | 提取结果 | 来源 |
|---|---|---|---|
| yidianzixun.com | 一点资讯 | **一点资讯** | title |
| bizhi66.com | 4k壁纸 - 高清壁纸下载 - 电脑桌面壁纸网站 - 壁纸爱好者 | **4k壁纸** | title |
| baibian365.com | 百变桌面 - 提供4K壁纸,高清桌面背景图片,4K高清壁纸下载 | **百变桌面** | title |

三个站都没有 `og:site_name`，靠 `<title>` 规则就能出名字 → **「自动获取」能力本身有效，只是没作用到这些历史条目上**。注意 `4k壁纸` 是营销式首段、不是官方站名，直接拿去当目录名不理想，人工校正（预置表）有价值。

### 证据 3：静态接线盘点

| 检查项 | 结果 |
|---|---|
| `library.html` 脚本清单 | 有 `js/site-name.js` / `site-name-store.js` / `site-registry.js` / `site-names-preset.js`，**没有** `js/library/settings.js`（它只在 `options.html:1428` 加载） |
| 全仓 `VRSiteNameStore.ready()` | `background.js:1000`、`settings.js:1284/1301/1349`。**库页 0 处** |
| 全仓 `VRSiteRegistry.refresh()` | 除模块内定义，**0 处外部调用**（`ensure()` 只在 `index === null` 时建一次，之后永不重建） |
| 根目录 vs `dist/` | `site-registry.js` / `site-name-store.js` / `site-names-preset.js` 完全一致；`app.js` 有差异但是 UI 货架改动，与站名逻辑无关，两个版本的结论一样 |
| 真机核对 | **未做**：调试端口 `127.0.0.1:9480` 未监听，本轮没有连真机，因此「真实 `vrSiteNames` 里有没有这三个域名」尚未核实。但**无论有没有，BUG-1 / BUG-2 都成立**（有 → 读不到；没有 → 更读不到），不影响修复顺序。这一项按 D1 铁律标记 **REVIEW**，不静默判过。 |

## 五、修复方案（分档，精确到文件/函数）

| 编号 | 优先级 | 改哪里 | 改什么 | 效果 | 风险 |
|---|---|---|---|---|---|
| **F1** | P0 | `js/library/app.js` `boot()`（3759 行，`async`） | 在 `await load()` **之前**加：<br>`await root.VRSiteNameStore.ready();`<br>`root.VRSiteRegistry.refresh();`<br>（try/catch 包住，读失败不影响浏览） | learned 层真正生效；以后任何小站下载一次就自动有名字 | 低。⚠️ `app.js` 正被另一编程会话修改（11-10 00:28 有改动，`dist/` 落后），**要由那条线合入或等它空闲，别并发写** |
| **F2** | P0 | `js/library/site-registry.js:267 nameOf()` | 精确查不到时补一次归一：`index[registrable(k)]`；`dirOf()` 同理 | `www.bizhi66.com` / `www.xiaohongshu.com` 能命中；分组不再因 `www.` 裂开 | 低，只增加回退、不改变已有命中；跑 `test-site-name.js` / `test-path.js` 回归 |
| **F3** | P1（最快见效） | `js/library/site-names-preset.js` | 补 3 条：`yidianzixun.com → 一点资讯`、`bizhi66.com → 壁纸66`、`baibian365.com → 百变桌面`（名字等苏哥定） | 预置表在库页**无条件生效**，改完刷新，截图里 3 个域名立刻变名字，不依赖 F1/F2 | 极低。改完必须跑 `node tools/check-site-names.js`（host 格式/显示名唯一） |
| **F4** | P1/P2（治本，需拍板） | 设置页/库页 + `background.js` `vrSiteNameProbe` | 加「一键补齐库中未知站点名」：扫描库内 `nameOf()===''` 的域名 → 串行调现有 `vrSiteNameProbe`（fetch 首页 → `parseHtmlInfo` → 写 store → `refresh` + 重绘）；限速、失败不阻塞、只登记不自动改目录 | 以后任何历史小站都能自动补名字，不再靠预置表人肉追 | 中：**会外发公开首页 HTTP 请求**（现有 probe 已 `credentials:'omit'`，不带登录态）；需苏哥拍板是否允许、是否只手动触发 |
| **F5** | P2 | `tools/test-site-name.js` | 补两组断言：①库页冷启动接线（ready 前后 `nameOf` 差异）②`www.` 归一 | 防止再退化 | 无 |

**推荐顺序**：F3 先让截图立刻变好 → F1 + F2 让「自动获取」真正通到界面 → F4 治本（拍板后）→ F5 补回归。
**明确不动**：下载链路（`background.js` 的 `vrResolveSiteName` / `VRPath.buildRelDir`），它本来就对。
