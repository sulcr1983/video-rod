## 0. 结论（大白话版）

**病根一句话**：现在"这条视频配哪段文字"靠一个**全页面共享的记事本**（`window.__vrFeedMeta`）——谁最后被点一下，记事本上写的就是谁的名字。列表页里你下载 A 微博的视频，记事本上还留着之前点过的 B 微博的文字（或者干脆过期了，退回页面级标题如 "AI总结"），于是就错了。

**修法一句话**：别靠记事本，靠 **GPS 定位**——浮标本来就贴在某条视频上，点下载那一刻从这条视频往上找它所属的内容卡片，**现场抄这条内容的文字**，随下载请求一起带去后台。全程不再有"记事本"，自然不会张冠李戴。

**外部调研结论**：星愿闭源看不到代码，但其交互（每条视频上独立的悬浮下载按钮）本质就是 DOM 锚定；开源界成熟做法两派——**DOM 锚定派**（按钮插在每条内容卡里，闭包天然知道"自己是哪条"）和**网络响应锚定派**（拦截 API 响应，媒体 URL 和文案在同一个 JSON 对象里天然成对）。这两条路本项目**都已有成功先例**：图片侧 `image-hover.js` 的 `nearestCard`，小红书的 MAIN world 注入桥。本方案一期用 DOM 锚定（改动小、命中率高），二期再上 API 锚定兜底。

## 1. 现状链路与病根定位（代码证据）

### 1.1 三条下载入口的文字来源

| 入口 | 文字来源 | 列表页（多条目）行为 | 单页行为 |
|---|---|---|---|
| 浮标/面板下载 | `vrPageMetaInTab` → 读 `window.__vrFeedMeta`（**整页单点全局，30 分钟 TTL**）；空/过期则回退 `extractPageInfo` → `document.title` | **张冠李戴**：取"最后一次点过的卡片"的文字，与本次下载的视频无关；全局空时统一变成页面标题 | 正常（页面本来就一条） |
| popup 批量/单卡 | 全局 `pageInfo = extractPageInfo(document)`，喂给**所有**媒体项套同一标题 | **统一同名**：所有 item 共享页面级标题（B-46 同源） | 正常 |
| 右键 `vr-video-save` | `runCommands(menuItemId)` **在全仓源码中无定义**（疑似 legacy 断裂路由），拿不到 per-post 文字 | 无绑定能力 | 不可靠 |

## 2. 外部调研：别人的扩展是怎么绑对的

### 2.1 星愿浏览器（Twinkstar）

闭源，无公开实现文档。可观察到的行为：每条视频/图片上有**独立的悬浮下载按钮**，点谁下谁、文字跟着谁走——这正是 **DOM 锚定**交互：按钮的挂载位置本身就是"我是哪条内容"的锚点，点击瞬间即可现场取文字，无需跨时间保存状态。结论：行为模式与本项目浮标一致，浮标挂载点即天然锚点，我们缺的只是"点下载时从锚点现场取文字"这一步。

### 2.2 开源油猴脚本两派（GreasyFork / GitHub 实测代码）

| 派别 | 代表 | 做法 | 优点 | 缺点 |
|---|---|---|---|---|
| **DOM 锚定派** | Mr.Po《微博 [图片\|视频] 下载》（4.5 万安装）、《微博视频下载助手》等 | 下载按钮**插进每条微博卡片内部**，click 闭包持有该卡片上下文，从卡片内取 `video src` 与文字 | 绑定 100% 直觉正确；零额外请求 | 依赖站点 DOM 结构（对通用扩展不可行，但"从媒体元素反查卡片"的思路通用） |
| **网络响应锚定派** | iiiLab 解析站、各拦截型脚本（fetch/XHR monkey-patch） | 拦截 API JSON：微博接口里 `mblog.page_info.media_info.video_url` 与 `mblog.text`/`user.screen_name` **在同一个对象里天然成对**，建 URL→文字索引，嗅探到 URL 查表即得 | 绑定最准、不受 DOM 改版影响 | MV3 的 SW webRequest **看不到响应体**，必须在页面 MAIN world 注入 hook + 桥回传；有性能与维护成本 |

### 2.3 与本项目已有资产的对照

| 外部做法 | 本项目已有先例 | 状态 |
|---|---|---|
| DOM 锚定（nearest card） | `image-hover.js` 的 `nearestCard`/`pageTitle`/`pageAuthor`，逐图带 meta | ✅ 已在图片侧稳定运行 |
| 网络响应锚定（MAIN world 桥） | 小红书通道：MAIN world 注入 + CustomEvent 桥（对抗性审计确认过的成熟通道） | ✅ 通道已踩通 |
| 播放时锚定 | `bulk-profile.js` `onPlay` 把 meta 绑到具体 video item | ⚠️ 有，但依赖全局当前值 |

**结论：不需要发明新东西，把图片侧已验证的范式平移到视频侧即可。**

### 苏哥拍板 + 专家决策（2026-11-12）

- **第一性原理（苏哥）**：首页那么多视频，点下载就要图文一致，最好还要兼容最高清探测；做不到就取消首页这个功能，否则下了也没法用。
- **专家决策**：**不取消功能，照样做，且把"最高清"一起锁进首页契约。** 理由：
  1. **两件事互不打架**。刚落地的微博 4K 最高清探测（B-76，`vrWeiboHdProbe`/变体探测）走浮标 `wantBest` 通道问站点接口拿清晰度；图文锚定走"浮标贴在哪条视频 → 现场抄那条文字"。二者在浮标按下去的同一瞬间各干各的，同轴不冲突。→ **首页浮标下载 = 精准文字 + 最高清**。
  2. **取消是下策**。真病是"文字串台"，不是"下载没用"。锚定修对后下下来的既对版又最高清，比砍掉入口强。
  3. **最坏护栏**：极个别页面结构抽不到卡片时，该条退化成"站点+日期+序号"安全命名，**绝不串成别人的文字**——守住"下了也没法用"的底线。
- 据此，原 §6 四项待拍板全部按推荐项落定（见 §6）。

## 3. 修复方案

### 3.1 一期主修：DOM 锚定 + meta 随消息（推荐先做）

改动集中在 3 个文件，入库层（E9）不动。

**M-A 浮标侧（`js/video-overlay.js`）——核心修复**

1. 浮标挂载时本就认领了具体 `<video>`（BOUND 数组）。`start(optionId)` 触发下载时，从**浮标当前挂载的那条 video 元素**出发，调用通用函数 `vrNearestTextCard(media)` 向上找"最近的同时包含独立文字块的祖先卡片"，现场抽取 `author/authorId/title/post`。
2. `vrVideoDownload` 消息增加 `meta` 字段，把现场抽取结果随消息带出（E1 修复点）。
3. **通用化（ADR-047 合规）**：`vrNearestTextCard` 不写微博选择器特例，用通用启发式——向上逐层找"包含足够长度独立文本（如 ≥15 字的 p/span/article 直系文本块）或作者署名链接的最近祖先"；微博/小红书/抖音等 feed 天然命中，无结构页面自然落到"无卡片"分支。实现上**优先把 `image-hover.js` 的 `nearestCard` 抽成公共模块**供图片/视频两路复用，避免两份启发式漂移。
4. 微博专属的 `__vrFeedMeta` 点击捕获段（E3，`:461-509`）**降级保留为兜底**（浮标未挂载/直接从面板点下载的场景），或直接随 M-D 拍板废弃。

**M-B SW 侧（`js/background.js`）**

1. `vrVideoDownload` 处理处：消息内 `meta` **优先级最高**（`metaOverride` 之前），其次是各站已有 `vrVideoOptions.out.meta` 通道，再才是 `vrPageMetaInTab`（旧全局兜底），最后 `extractPageInfo` 页面级。
2. 页面级兜底加"宁缺勿错"护栏：**仅单视频页/详情页场景才允许页面级 title 进 post**；列表页（可检测到 ≥2 个内容卡片）若 DOM 锚定失败，宁可 post 置空、文件名退化为 `${site}_${date}_${index}_${ext}`，也不要错绑（错绑比没有更伤媒体库）。

**M-C popup 批量侧（`js/popup-videorod.js`）——B-46 视频面**

1. 停止"一个全局 `pageInfo` 喂所有卡片"。列表页检测到多卡片时：对 popup 列表中每个 item，按其 `pageDOM`/URL 无法反查卡片的，命名退化为安全档（site+date+index）；后续二期接 URL 索引后升级为 per-item 精准命名。
2. 保留小红书既有重标逻辑（`vrXhsScan` 通道）不变，M-2 单点注入+重算、重算前清 `downFileName` 防套娃（BUG-M2-1）等既有约束继续生效。

**M-D 附带修缮**

1. 右键 `runCommands` 断裂（E 路由无定义）：确认为死代码则移除菜单项 `vr-video-save`，或补齐实现走 M-B 同一条 meta 优先级链（交编程会话实测判定，本方案不预设）。
2. `bulk-profile.js` `onPlay` 的 per-item 绑定改读"现场锚定"结果，去掉对全局当前值的依赖。

**M-E 首页契约：图文一致 + 最高清同通道（关键）**

首页浮标下载必须同时保证两条：
1. **文字锚定**（M-A）——按本方案现场抽取，不串台；
2. **最高清**（B-76 已落地）——浮标 `start(optionId, true)` 的大图标一键最高清 + 清晰度菜单选定档位，已走 `vrWeiboHdProbe`/变体探测；列表页每条微博的视频各自问各自的 `media_id`（归族按 media_id，B-76 已修），与文字锚定互不干扰。
施工人员只需确认：列表页浮标下载路径同时调用"现场锚定"与"最高清探测"两路，且两者结果（meta + 各档 URL）在同一 `vrVideoDownload` 消息/响应内聚合，不互相覆盖。验收用例必须包含"首页两条不同微博 → 各自的图+文+各自最高清档位"三项同时正确。

### 3.2 二期增强：网络响应锚定（URL 索引，P2 排期）

MAIN world 注入 hook `fetch`/`XMLHttpRequest`，对 JSON 响应做**通用规则扫描**（不判站点）：同一 JSON 对象（或近邻层级）同时出现媒体直链字段（`video_url`/`play_url`/`url` 等）与文本字段（`text`/`title`/`content`/`description`）时，登记 `urlKey → {title, post, author, authorId}` 进页内索引，经 CustomEvent 桥同步给 content script / SW 嗅探层。嗅探到媒体 URL 时查表，命中即得 per-item 精准文字，popup 批量也因此升级。复用小红书通道的全部踩坑经验（executeScript args 拒收 undefined、幂等探针等）。二期做完后，一期 DOM 锚定退为兜底。

### 3.3 明确不做

- 不做微博/任何站点的 DOM 选择器特例堆砌（ADR-047）。
- 不动 `js/templates.js` 模板引擎与 `js/library/*` 入库层——上游 meta 对了它们即对。

## 4. 风险与边界

| 风险 | 应对 |
|---|---|
| 微博 feed 点击后 `<video>` 被搬到全屏播放层，DOM 上溯失效 | 列表页浮标挂在**原卡片内**的 video 上，此时上溯有效；已进播放层=单条内容页，页面级提取本来就对。上溯失败自然落兜底，不炸 |
| 虚拟滚动 DOM 复用导致卡片文字抽错 | 现场抽取发生在"点下载瞬间"，读到的是当前 DOM 快照，与滚动复用窗口极小；二期 URL 索引可彻底免疫 |
| feed 卡片结构改版（哈希化选择器失效——小红书 B-45 教训） | 通用启发式不依赖具体 class；兜底退化命名保证"不错只缺" |
| 通用启发式在奇异页面误抓广告位文字 | 文本块长度阈值 + 卡片需含署名/时间等 feed 特征才认定；抽不到即退化 |
| 与另一编程会话并发改 `video-overlay.js`/`background.js` | 施工前 git baseline，本方案文档为唯一真源，改动范围锁定在 §3.1 所列函数 |

## 5. 验收标准（交编程会话执行）

1. **主场景**：微博首页（多条微博混排）——对 A、B 两条不同微博分别用浮标下载视频，媒体库详情各自 `title/author` 与对应微博一致，0 错绑；重复三组不同顺序点击验证时序无关性。
2. **兜底态**：刷新页面后不点卡片直接悬停下载 → 文件名退化安全档（site+date+index），不出现别的微博的文字，也不出现无关页面标题。
3. **单页回归**：微博单视频页、B站单 P、YouTube 单视频下载命名与现状一致（不回归）。
4. **popup 批量回归**：微博首页 popup 批量下载，不再出现全列表同名；小红书既有通道 14/14 用例不回归。
5. **右键入口**：`vr-video-save` 实测可达则走新 meta 链验证绑定；确认为死代码则菜单项消失、无 console 报错。
6. 按 `docs/TEST-ASSETS.md` 真源补微博首页多条目素材条目；测试纪律按 `docs/TESTING.md` §1 有头 e2e 实例铁律执行。
