# 钓鱼竿 video-rod 施工计划 v1

> 配套：PLAN.md（方案书 v1.3）+ popup-prototype.html（交互原型 v5）
> 策略：**外壳大改、内核不动**——猫抓的嗅探内核/下载器/FFmpeg 合并一律不碰，保证随时能 cherry-pick 上游更新；所有新功能以独立模块挂在壳上，一个模块坏不影响其他。
> 节奏：按里程碑推进，**每个里程碑结束都有可验收的实物**，不满意就地整改再往下走。全程 git 托管，每阶段一个回滚点。

## 一、里程碑总览

| 阶段 | 目标 | 预估 | 验收实物 |
|---|---|---|---|
| M0 地基 | 智能起名引擎 + 页面识别模块 | 1-2 天 | 输入任意网址，输出干净的文件名（控制台可验） |
| M1 面板 | popup 列表外科手术（改名/目录/清晰度/分P/筛选） | 2-3 天 | 加载扩展，面板和原型长得一样 |
| M2 下载 | 带目录下载 + 批量队列 + 去重 | 2 天 | 测试站视频真实落进 Downloads/video-rod/xxx/ |
| M3 B站 | 分P/合集/大会员主动抓取 + DASH 合并 | 3-4 天 | 一个 BV 号下一整部纪录片 |
| M4 YouTube | 播放列表/频道抓取 + 签名 + 合并 | 3-4 天 | 一个播放列表链接全下 |
| M5 周边 | 图片批量 + 右键秒存 + 快捷键 + 完成提示 | 2-3 天 | 小红书图片批量存、右键直接下 |
| M6 打磨 | 细节打磨 + 全功能回归 + 使用说明 | 1-2 天 | 交给苏哥日常用的成品 |

合计约 **2-3 周**（每天投入几小时的节奏；集中赶工可压缩到一周内）。

## 二、为什么这个顺序

```
M0 命名引擎 ──► M1 面板 ──► M2 下载管线 ──┬──► M3 B站解析 ──┐
                                        └──► M4 YouTube ──┼──► M5 周边 ──► M6 打磨
                                                          │
   （地基）      （外壳）      （管道）        （两家硬骨头，可并行或二选一先做）
```

- **M0 最先**：起名是全局依赖——每个下载动作都要用它，先造好，后面所有模块直接调用
- **M1-M2 是主干**：面板+下载管着日常体验，做完就已经是个能用的工具了（视频嗅探+改名+分目录+批量）
- **M3/M4 放后面**：两家破解是独立模块，谁先做谁后做互不影响；如果其中一家踩坑（站点改版），先上另一家，不阻塞
- **M5 最后**：图片/右键/快捷键都是锦上添花，挂在成熟的主干上最省事

## 三、每个阶段干什么（大白话版）

### M0 地基：起名引擎 + 认页面（1-2 天）
- 给模板引擎加新变量：作者（昵称@ID）、正文、序号——B站签名的 JS 实现直接抄开源库
- “认页面”模块：文章页取标题剥网站名、推特页取正文和作者、认不出就退回网页标题
- 清洗三件套：非法字符换下划线、超长截 60 字、重名自动加序号；拿不到的信息自动跳过不留空
- **验收**：拿 10 个真实网址（新闻/推特/B站/普通页）跑一遍，输出文件名个个干净

### M1 面板：列表大改（2-3 天）
- 照原型 v5 重做列表卡片：文件名随手改、目录 chip（默认目录/最近/新建）、清晰度下拉（默认自动最高）、B站卡带「分P ×N」
- 底部操作栏：全选/批量命名/批量下载 + 顶部类型筛选（全部/视频/图片/流媒体）
- 设置抽屉：默认目录、命名模板、图片嗅探、主动抓取等开关
- **验收**：扩展装上，面板和原型一模一样；所有按钮可点有反馈

### M2 下载：真落盘（2 天）
- 下载带目录：`Downloads/video-rod/平台/作者/名字.mp4`
- 批量队列：勾选几条就排队下几条，错峰不卡浏览器，完成面板内汇报
- 去重：同一个地址下过就记住，防手残重复下
- **验收**：测试站勾 5 个视频批量下，文件夹里整整齐齐

### M3 B站模块（3-4 天，第一个硬骨头）
- 抄 `bilibili-API-collect` 的 WBI 签名 + playurl 全链路；分P列表一次抓全
- DASH 音视频分离流 → 复用猫抓的 FFmpeg 合并成完整 MP4
- 大会员内容借登录 cookie；失效自动退回嗅探模式
- **验收**：随便找个多P纪录片/番剧，一个链接全下；再找个大会员视频验证登录态

### M4 YouTube 模块（3-4 天，第二个硬骨头）
- 抄 `avi12/youtube-downloader` 的提取逻辑：读页面数据 + 签名 decipher + ffmpeg.wasm 合并音视频字幕
- 播放列表/频道全抓（只抓已加载项，不自动滚动）
- **验收**：播放列表链接全下；会员视频（如有）验证

### M5 周边补齐（2-3 天）
- 图片批量：扫页面（img/背景图/懒加载）+ 滤小图 + 和视频同款卡片管理
- 右键秒存：网页视频/图片右键直接下（抄 VDH）
- 快捷键 Alt+Shift+V 唤起面板
- **验收**：小红书/微博图片批量存；右键视频直接落盘

### M6 打磨交付（1-2 天）
- 空状态、错误提示、深色细节；全功能回归一轮
- 写一份大白话使用说明
- **验收**：苏哥日常随便用，找不到茬

## 四、丑话说前面（风险与对策）

| 风险 | 影响 | 对策 |
|---|---|---|
| B站/YouTube 改接口或签名 | M3/M4 失效 | 模块独立+失效自动退回嗅探；抄的开源库本身会跟更新 |
| B站 WBI 密钥每天轮换 | 偶尔 403 | 按开源实现的缓存策略走（24h 刷新） |
| YouTube 签名 decipher 复杂 | M4 周期拉长 | 直接集成 avi12 的成熟代码，不自己重写 |
| Chrome 大版本禁 unpacked | 扩展掉线 | 重装一次即可，配置在 profile 里不丢 |
| 改造改坏猫抓内核 | 全盘崩 | 内核不动；每阶段 git 回滚点，坏就退 |
