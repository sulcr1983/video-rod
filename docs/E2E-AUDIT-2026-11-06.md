## 3. 本轮修复

1. **微博批量落盘**：不再走页面 `<a download>`；改为带 `filename`/meta 的下载器，403 时由离屏扩展 fetch 取流后回写资源库，修复只落 1 条错误文件、platform/type 为空。
2. **小红书图片 403**：扫描改用 `infoList` 的 `WB_DFT` 完整 URL，保留 `!nd_dft_*` 后缀并强制 HTTPS；旧逻辑剥后缀得到裸地址，A2 五张全失败。
3. **Instagram 下载按钮**：路径正则支持 `/用户名/reel/<短码>`，此前只认 `/reel/<短码>`，导致 Reel 页没有按钮。
4. **`live-eval --sw`**：连接 Service Worker 时跳过不支持的 `Page.enable`，否则无法直接诊断后台函数。
5. **测试基线同步**：`test-path`/`test-image-util` 仍按旧“待整理 / 600px”断言，和当前 `@ID / 域名占位`、`500 长边 + 200 短边` 实现不一致；已改成对当前实现的精确断言，未降低断言强度。

## 4. 已知限制与未完成项

- **`download-path 6/10`**：测试前提是“无 FSA 目录授权”，但 Chrome 147+ 在该条件下会忽略 `filename`，blob 落成 UUID。与 ADR-040 同源，不是本轮引入；要 10/10 必须先授权资源库根目录，或改测试为授权态用例。
- **TikTok**：当前页面只给 blob/MSE，页面内嵌探针无直链；这是站点侧限制，不是通用通道代码崩溃。
- **`download-path`** 仍应在有 FSA 授权的真实 profile 上补一条 10/10 用例；本轮未做。
- 本轮没有执行 `e2e-all --live`（会重复访问真实站点，风控风险），真实站点结论来自上面的定向验证。
