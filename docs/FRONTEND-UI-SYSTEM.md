# 前端统一重设计：popup + 资源库

> 日期：2026-10-24 ｜ 状态：已实施并验收（见 §10） ｜ 依据：`ui-ux-pro-max` 设计规范 + 现有 popup/资源库原型审计
> 目标：popup（400px 面板）与资源库（独立页面）共用一套 token、组件与交互语言，同时**不改任何既有 ID / 事件 / 存储键**。

## 2. popup 审计

优点（保留）：400px 定宽、66px 单行、每行只放一个主控件（勾选）、底部固定「全选 → 批量命名 → 批量下载」、唯一主按钮。

问题：

1. **强调色与设置页不一致**：popup 用深青 `#0f6e63`，设置页用蓝 `#1a73e8`；底部主按钮又是墨黑 `#16181d`，三个界面三种主色。
2. **头部三层**（品牌行 / 站点行 / 筛选行）共约 110px，在 600px 高面板里占掉 1/5。
3. **字号偏小**：导航 10.5px、徽章 9px、说明 9.5px，长时间看清吃力；对比度虽够，但信息密度过高。
4. **可点击区域偏小**：行内勾选框 16px、图标按钮 27px，均低于 32px 推荐值。
5. **空态只有一句“还没闻到味儿~”**，没有「刷新 / 打开设置」的下一步。
6. **面板内设置视图用原生 checkbox**（`.sw` 31px），与设置页的 44×24 开关不是一套。
7. 缺少统一的 `:focus-visible` 焦点环。

---

## 3. 资源库原型审计

原型（v1.3）已具备：顶栏搜索、平台/博主侧栏、网格卡片、缩略图、星标、缺失标灰。

问题：

1. **没有真数据**：27 条演示数据写在 HTML 里，未接 `VRDB`/`VRIndex`。
2. **控件密度过高**：顶栏 5 个动作（评审说明 / 命名规则 / 三视图 / 刷新 / 批量），侧栏平台 + 博主两组长列表，首屏视线无处落。
3. **视觉语言与设置页/ popup 不一致**：圆角、字号、卡片阴影各一套。
4. **卡片信息层次弱**：文件名、博主、大小、日期字号接近，扫读困难。
5. **缺少空态 / 缺失态 / 加载态**的完整设计。
6. **窄窗口无方案**：`>1200px` 之外没有断点。

## 4. 统一设计 token

沿用设置页蓝灰系统，popup 只换强调色，不动布局：

| Token | 值 | 用途 |
|---|---|---|
| `--vr-accent` | `#1a73e8` | 主按钮、选中、链接 |
| `--vr-accent-strong` | `#1765cc` | hover |
| `--vr-accent-weak` | `#e8f0fe` | 选中底色 |
| `--vr-ink` | `#111827` | 标题/正文 |
| `--vr-text-2` | `#5b6472` | 次要 |
| `--vr-text-3` | `#8a94a3` | 弱化/占位 |
| `--vr-line` | `#eef1f6` | 行分隔 |
| `--vr-line-2` | `#e3e8ef` | 控件边框 |
| `--vr-surface` | `#ffffff` | 卡片 |
| `--vr-surface-2` | `#f6f8fb` | 页面底色/次级块 |
| `--vr-danger` | `#b91c1c` | 缺失/错误 |
| 圆角 | 8 / 10 / 12 | 控件 / 卡片 / 页面容器 |
| 字号 | 11 / 12 / 13 / 18 / 22 | 徽章 / 辅助 / 正文 / 分区 / 页面 |

深色模式：popup 现有浅色定宽面板不做深色（浏览器 popup 不跟随页面主题），资源库页面跟随 `prefers-color-scheme`。

## 5. 组件规范

- **按钮**：主（蓝底白字）/ 次（白底描边）/ 幽灵（无边框）/ 危险（红字红边）；高度 30–36px。
- **筛选 chip**：胶囊，选中蓝底浅色 + 蓝字；不再用下划线。
- **卡片**：白底、1px `--vr-line-2`、10px 圆角、hover 上浮 1px + 轻阴影。
- **输入**：34px 高、8px 圆角、聚焦蓝环 2px。
- **开关**：36×20 或 44×24，开启蓝色。
- **徽章**：类型用浅色底 + 深色字（视频/图片/音频/流媒体），缺失用红色描边。

## 6. popup 改造方案（不改结构/ID）

1. 强调色统一为蓝：`--vr-cyan*` 全部映射到 accent token；底部主按钮由墨黑改蓝。
2. 头部保留两层：品牌行（logo + 名称 + 版本 + 设置）+ 站点/页签行；筛选行改为**胶囊 chip**，高度从 34px 降到 32px。
3. 字号整体 +0.5~1px：导航 11px、徽章 9.5px、说明 10px；行高不变，仍保持 66px。
4. 勾选框 16→18px；图标按钮 27→30px；补 `:focus-visible` 2px 蓝环。
5. 空态：保留「还没闻到味儿~」文案，下方加一行「刷新页面 / 检查设置」的说明（纯 CSS/静态，不引新交互）。
6. 面板内设置视图的开关统一为蓝色轨道（复用 `.sw`，只改颜色）。
7. 保持：所有 ID、`#down` 三按钮、`.panel` 66px 行、`.Tabs/.TabButton` 结构、`#filter/#features` 浮层定位。

## 7. 资源库页面（S3 核心）

### 布局

```
┌ topbar 60px：品牌 / 搜索 / 刷新 / 设置 ──────────────────────┐
├ sidebar 232px ──┬ main（max 1280）───────────────────────────┤
│ 全部 / 视频 /   │ 标题 + 数量         排序 / 网格·列表        │
│ 图片 / 音频 /   │ 筛选 chip（平台/博主 可清除）                │
│ 星标            │ ┌ card ┐┌ card ┐┌ card ┐┌ card ┐            │
│ 平台 …          │ │ 缩略 ││ 缩略 ││ 缩略 ││ 缩略 │            │
│ 博主 …          │ └──────┘└──────┘└──────┘└──────┘            │
│ 根目录信息      │ 空态 / 缺失态                               │
└─────────────────┴────────────────────────────────────────────┘
```

### 功能（S3 核心，不含 S4 灯箱/S5 回收站）

- 数据：`VRDB.getAllFiles()`；页面打开时若索引为空，提示「去设置页重建索引」。
- 筛选：类型（全部/视频/图片/音频）、星标、平台、博主；侧栏显示计数。
- 搜索：文件名 / 标题 / 博主，150ms 防抖。
- 排序：最新 / 名称 / 大小。
- 视图：网格（全宽 4:3 大卡）/ 列表（紧凑行）；单击卡片打开全屏查看器。
- 缩略图：`VRThumbs` 队列并发 2、懒生成、WebP 存 `thumb` store；失败显示类型占位。
- 卡片：类型徽章、时长/大小、文件名、平台·博主、星标；缺失文件标灰 + 红标。
- 交互：单击卡片全屏预览（图片/视频，←/→ 翻页、Esc 关闭）；查看器内可「在文件中打开」；星标即时写库。
- 空态：区分「没有资源」与「筛选无结果」，给「清空筛选」按钮。

### 响应式

| 断点 | 行为 |
|---|---|
| ≥1200 | 侧栏 232px，卡片 4 列 |
| 900–1199 | 侧栏 200px，卡片 3 列 |
| 700–899 | 侧栏折叠为顶部筛选条，卡片 2 列 |
| <700 | 单列，隐藏次要元信息 |

## 11. 资源库 v2：向原型对齐 + 数据可视化（2026-10-24）

> 触发：v1 上线后对照 `deliverables/prototypes/library-prototype-v1.html`，视觉密度和结构层次差距明显——「一堆文字排列、没有表格、没有间隔」。
> 结论：v1 只做到了「能筛能看」，丢了原型的**信息可视化**和**桌面软件质感**。v2 按下面 6 条重做。

### 11.1 差距诊断（逐项对照）

| 维度 | 原型 | v1 实现 | 判定 |
|---|---|---|---|
| 数据可视化 | 博主速览卡（头像 + 4 格拼图 + 图/视频计数） | 无 | ❌ 缺 |
| 概览指标 | 侧栏计数 + 顶部总数 | 只有一行「共 N 项 · X MB」 | ❌ 太弱 |
| 分布呈现 | 平台色点、类型 tab 计数 | 纯文字列表 | ❌ 无图形 |
| 列表视图 | —（原型为紧凑行） | `div` 拼的行，无表头，列不对齐 | ❌ 不像表格 |
| 卡片信息 | 类型标、时长、悬停动作、悬停放大 | 角标 + 星标，信息挤在 3 行 | ⚠️ 平 |
| 间距 | 22px 页边、14px 卡间距、20px 区块间距 | 16–22px 混用，区块间无留白 | ❌ 挤 |
| 侧栏层次 | 分组标题 + 图标 + 计数 + 底部根目录块 | 分组有，但无图标/色点，底部一行字 | ⚠️ 平 |

### 11.2 v2 结构

```
┌ topbar：品牌 / 搜索 / 网格·列表 / 刷新 / 设置 ────────────────┐
├ sidebar 248 ─┬ main ─────────────────────────────────────────┤
│ 平台（色点+条）│ 面包屑 / 标题 + 数量 + 排序 + 分组            │
│ 博主（头像）  │ ┌ 概览：4 个 KPI ┐┌ 平台分布堆叠条 ┐┌ 博主 Top5 ┐│
│              │ └───────────────┘└───────────────┘└──────────┘│
│              │ 类型 tabs（全部/视频/图片/音频/星标，带计数）    │
│ 根目录块      │ 博主速览卡（头像 + 拼图）                      │
│              │ 网格大卡 / 表格（表头 + 对齐列 + 斑马纹）       │
└──────────────┴───────────────────────────────────────────────┘
```

**三条原则**

1. **数字先说话**：任何「有多少」都用大号数字 + 单位 + 占比条，而不是一句话。
2. **能对齐就对齐**：列表用真 `<table>`，表头固定、数字列右对齐、等宽数字。
3. **区块要呼吸**：页边 28px、区块间距 26px、卡片间距 16px；分组用 `section-label` 细线分隔。

## 12. 查看器 v2（S4）与概览收起（2026-10-24）

### 12.1 概览收起

- 概览默认**收起**，只保留一行摘要：`资源概览 · 6 项 · 742 MB · 4 个平台  [展开]`。
- 展开状态写 `localStorage.vrLibOverview`（`1` 展开 / `0` 收起），刷新后保持。
- 表格视图强制收起概览与博主速览（管理视图优先）；切回网格时恢复用户选择。

### 12.2 查看器结构

## 13. 删除与回收站（S5）

### 13.1 口径

1. **默认软删除**：文件移到 `<根>/_回收站/<批次>/<原相对路径>`，保留目录结构；批次 = `YYYYMMDD-HHmmss-xxxx`。
2. **批次清单**：`_回收站/<批次>/_manifest.json` 记录每个条目的完整索引字段（平台/博主/大小/时长/来源…），即使 IDB 被清空也能按清单恢复。
3. **恢复**：原路径空着才恢复；目标已存在则报 `LIB_E_EXISTS`，不覆盖。
4. **彻底删除**：只删回收站里的副本；「清空回收站」二次确认并明确不可恢复。
5. **索引同步**：删除成功 → `VRDB.deleteFiles()`；恢复 → `VRDB.putFiles()`。
6. **审计**：每次操作写 `<根>/_migration/ops-<时间戳>.json`（动作/批次/条目/结果），失败不阻断主流程。
7. **权限**：需要 `readwrite` 目录句柄；没有句柄或权限时返回 `LIB_E_NO_PERM`，界面提示去设置页「授权目录并全量扫描」，不静默失败。
8. **缺失文件**：索引里 `state: missing` 的条目，删除时只清索引（没有文件可移）。

### 13.2 引擎 API（`js/library/trash.js`）

| 方法 | 说明 | 返回 |
|---|---|---|
| `remove(relPaths)` | 批量移到回收站（单次一个批次） | `{batch, moved, cleaned, failed[]}` |
| `list()` | 扫描 `_回收站` 读批次清单 | `[{batch, at, size, items[]}]` |
| `restore(batch, relPath?)` | 恢复单条 / 整批 | `{restored, failed[]}` |
| `purge(batch, relPath?)` | 彻底删除单条 / 整批 | `{purged, failed[]}` |
| `empty()` | 清空全部批次 | `{batches, purged}` |
| `status()` | 徽标用 | `{count, size, batches}` |
