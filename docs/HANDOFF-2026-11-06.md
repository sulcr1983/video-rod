## 6. 关键根因档案（诊断时先看这里，能省几小时）

### ① X 批量三连问题 = 一个 URL bug（最容易误判成「风控」）

**现象**：面板缩略图全裂、批量下载全失败、状态显示「连续失败 3 次，已暂停（可能触发风控）」。

**根因**：X 媒体 URL 有两种形态：
```
https://pbs.twimg.com/media/HWSp9nzXsAAazfF?format=jpg&name=medium   ← 无扩展名，靠 format 参数
https://pbs.twimg.com/media/HWTE5NjXsAA5oDT.jpg                       ← 有扩展名
```
旧代码一律 `raw.split('?')[0] + '?name=orig'`，把 `format=jpg` 丢了。

**实测证据**（浏览器内 fetch）：

| URL | HTTP |
|---|---|
| `.../HWSp9nzXsAAazfF?name=orig` | **404** |
| `.../HWSp9nzXsAAazfF?format=jpg&name=orig` | **200** |
| `.../HWSp9nzXsAAazfF.jpg?name=orig` | 200 |

**修法**：保留 `format`（或路径里的扩展名），缩略图另用 `name=small`。
**顺带的坑**：404 是「内容错误」，不该计入「连续失败→风控暂停」。已改为只有 403/网络错误才累计，且必须「没有一条成功过」才暂停。

### ② 资源库首屏永久空白（本轮新发现，最容易再踩）

**现象**：新开库页 0 卡片、0 文件；点一下「重新扫描」立刻出现 45 条。4 个标签里 3 个空。

**根因**：`bind()` 执行时抛 `ReferenceError: on is not defined` → 整个 `boot()` 中断 → `load()` 从未执行 → `FILES` 永远 `[]`。
触发源是往 `bindFavAndDrawer()` 里插了一个 `on('batchMove', …)`，而该闭包没有 `on` 这个局部帮助函数（`on` 只在 `bind()`/其他函数里定义）。

**诊断钩子（已留在代码里，可直接用）**：
```js
// 在库页执行
window.__vrBoot
// 正常：["start","bind","bindMissing","favs","root","load:45"]
// 中断：["start","bind-ERR:on is not defined"]
```
**教训**：`bind()` 里任何一处接线抛异常都会让整页空白，且外层 `try{}` 把它包装成「Uncaught (in promise)」，控制台堆栈只指向定义行，很难定位。**接新按钮一律用局部 `addEventListener` + 判空，不要依赖外层 `on`。**

### ③ 视频卡片/播放器没有预览图

`js/library/thumbs.js` 的 `loadVideoFrame()` 在 `draw()` 里**先 `cleanup()`（清 `src` + `load()`）再 `resolve(v)`**，调用方拿到 video 时帧已被清空 → canvas 画空白。
已改为先 `resolve(v)`，`setTimeout(cleanup, 0)` 延后清理。
另：8 秒超时对大文件太短（93MB/18.5MB 的 MP4 把 moov 放在尾部，10 秒内连 `loadedmetadata` 都不触发），视频单独给 30 秒 + seek 3 秒兜底。

### ④ 库根路径出现过两个值（需确认）

- 页面 `#rootBtn .rb-path` 显示 `F:\download\video-rod`
- 实际下载落在 `D:\personal\Downloads\video-rod`
- `VRIndex` 的 `absRoot` 从 `vrLibSettings.detectedRoot` 来（由 `chrome.downloads.search` 猜）

**风险**：库根指错会导致「扫描扫不到新文件」，症状和「重扫无效」一模一样。诊断时先核对：
```js
new Promise(r=>chrome.storage.local.get('vrLibSettings',d=>r(JSON.stringify(d.vrLibSettings))))
```

### ⑤ 下载 403 的真因不是「缺 Referer」，而是「多了 Origin」

扩展发起的请求自带 `Origin: chrome-extension://<id>`，sinaimg 等 CDN 会直接拒。curl 用同一 URL 不带 Origin 就是 200。
修法：DNR `modifyHeaders` 里 `referer: set` + **`origin: remove`**。此修复已在 `vrSetMediaHeaders` / `vrImgRefererRule`。

### ⑥ 批量下载「回执丢失 ≠ 失败」

`vrBulkDownload` 是长任务（3–5 秒/条 × N），`sendMessage` 的回执通道可能先断。原实现把「没回执」当「全部失败」，误报。
已改为以 `vrImg.batchProgress` / `vrBulkProgress` 广播为准。
