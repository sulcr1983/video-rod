## 1. 这次会话刚做了啥（按钮修复）

文件：`js/video-overlay.js`（本次新增，未提交）。

苏哥反馈原话：「按钮被一个图标遮住了。图标要大一些，放下面一些，不要和上面的那个图标重叠遮住了。」

改了三处：

1. **按钮放大**：主按钮 `44×40`（图标 21px），箭头 `26×40`（图标 14px），z-index 拉到 `2147483000`，保证压在播放器 UI 之上。
2. **往下让开播放器自己的顶部控件**：按钮不再贴着视频 `top+10`，而是按视频高度给一段距离 `dy = clamp(round(h*0.12), 16, 76)`。这样 B站 左上角的「音乐封面 / 关注头像」、微博 的作者名条不再和按钮叠一起。
3. **命中判定重构（重要，解决微博按钮不出现）**：原来靠 `video` 元素的 `mouseenter` 触发显隐。但微博/抖音/B站 都会在 `video` 上盖一层自己的覆盖层（封面、播放键、作者条），鼠标实际落在覆盖层上，`video` 收不到 `mouseenter` → 按钮永不出现。改成 `document` 上听 `mousemove`（60ms 节流），按 `video` 的矩形做命中判定，上面盖几层都不影响。

验证情况（真机，星愿 9223）：
- **B站**：按钮在 `top+74`（视频 616 高），四角取元素栈只剩 `VIDEO`，无重叠。✅
- **普通网页**（本地 `http://127.0.0.1:18080/index.html`）：`dy=22`，按钮出现正确。✅
- **微博**：`on:true` 出现过、dy 计算正确（305 高 → 37）；但微博首页 feed 是懒加载、内容随机，脚本多次没稳定截到图。**逻辑层面已修，建议明天在苏哥登录态浏览器里手动看一眼确认**。

> ⚠️ 一个测试坑（已解决）：用 CDP `Page.captureScreenshot` 截图，若用默认 `fromSurface:true` 在窗口被遮住时会拍到「没光栅化的残影」——表现就是按钮位置冒出一个**白底破图小方块**，看着像多了个图标。**这是截图伪影，不是真实 UI**。要拍干净用 `fromSurface:false`。已写进 `tools/overlay-check.py` 和 `tools/overlay-pos.py`，以后截图用它俩。

## 2. 抖音 bug（苏哥新报，本次只诊断没改）

苏哥原话：「抖音可以下载，但是下载的视频是错误的。而且起名也错了。没有 get 到这个人的 id 和标题」

URL 例子：`https://www.douyin.com/jingxuan/search/...?modal_id=7682668289420880313&type=general`

### 2.1 已锁定的两条根因

**根因 A — 命名错：命名引擎不认识抖音。**
`js/naming.js` 的站点规则表 `SITE_RULES`（约 135 行）只有 twitter / xiaohongshu / bilibili + 通用兜底 `article`。
抖音域名 `douyin.com` 匹配不到任何专用提取器 → 掉进 `extractArticle` 兜底。
- 兜底取 `og:title / h1 / document.title`：抖音页面的 `title` 多半是「抖音-记录美好生活」这类通用名，`h1`/`og:title` 也没有。
- 作者取 `meta author / .author / .byline`：抖音这些都没有 → `author` 和 `authorId` 全空。
- 结果：按模板 `${author}_${title}` 出来的文件名只剩一个没意义的 title，甚至直接用 `document.title`，自然「拿不到这个人的 id 和标题」。

**根因 B — 下错视频：通用站点现在「选体积最大的那个视频」。**
`js/background.js` 的 `vrVideoOptions`（约 1211 行）对通用站点：
```js
const list = (cacheData[tabId] || []).filter(m => ... VR_VIDEO_EXT.test(m.ext))
  .sort((a, b) => (b.size||0) - (a.size||0));   // 体积降序
out.options = list.slice(0, 6)...   // 一键下载取 options[0] = 最大那个
```
抖音一个页面挂着好几个视频（当前播放 + 推荐流 + 可能的广告/preview）。「选最大」≠ 你正在看的那个 → 下错视频。
另外抖音主流是 **HLS(m3u8)**，分片/列表本身不在 `VR_VIDEO_EXT`（只认 mp4/webm/mkv/.../ts/m4s）里，能被列成「视频」的往往是某个预览 mp4 或别处的直链，更容易选歪。

### 2.2 修复方向（草图，等实机确认，**先别闭眼写**）

1. **命名**：在 `js/naming.js` 加 `extractDouyin`（作者 = 抖音号/昵称，标题 = 视频描述），并在 `SITE_RULES` 加一条 `douyin.com` 匹配。
   - 抖音作者节点/描述节点的 class 这次没实探到（见 2.3 的复现前提），**明天在登录态浏览器里按 F12 实际看一下**：一般作者信息在「抖音号」「昵称」附近，视频描述在详情区。拿到确切 selector 再写提取器。
2. **选流**：`vrVideoOptions` 的通用分支把「选最大」改成「选**当前正在播放 / 视口内可见**的那个 `video` 对应的媒体」；或直接让抖音走类似 B站 的专属路径（页面主世界拿当前视频真实直链）。
   - 这个得看抖音到底给的是 mp4 直链还是 m3u8。如果是 m3u8，正好能复用 ADR-028 已经写好的 HLS 管线（offscreen 内解析+解密+合并）。**但抖音 m3u8 多半 AES-128 加密，ADR-028 的补记里记着「真实加密 HLS 还没在真机验过」，这是已知风险点。**

### 2.3 ⚠️ 复现前提（重要）

**抖音必须在苏哥真人登录态的浏览器里复现调试。** 我这次用 CDP 自动 `Target.createTarget` 打开苏哥给的 URL，结果抖音前端把 `modal_id` 参数剥掉、重定向回 `search/裸舞裤` 普通搜索页，`document.title` 空、`video` 数量 0 —— 典型的登录墙 / 反爬白页。**无头环境拿不到真实 DOM，没法分析。**

所以：明天让苏哥的星愿保持登录抖音，直接在那边打开视频详情页，再用 CDP 附着上去（别用 createTarget 新开，新开的没登录态），或干脆让苏哥手动点开视频后你再附着调试。

## 5. 坑 & 铁律（别再踩）

- **铁律：先搜后写。** 复杂功能/新依赖前先查 npm/GitHub/PyPI，有成熟轮子优先复用，新依赖要先给苏哥过目。
- **CDP 端口**：星愿调试端口是 `9223`（不是 Playwright 的 9226）。`curl --noproxy '*' http://127.0.0.1:9223/json/list` 看标签。
- **扩展重载**：改了扩展代码要 reload 才生效；内容脚本只在页面加载时注入，所以验证前**不仅要 reload 扩展，还要新开/刷新页面**。
- **截图伪影**：CDP 截图用 `fromSurface:false` 才干净，否则窗口被遮会拍出白底破图残影（见第 1 节）。
- **抖音不能 CDP 新开**：会掉登录态+反爬白页，必须附着苏哥已登录的标签页。
- **命名引擎**：加新站点先去 `js/naming.js` 的 `SITE_RULES` 加规则，别让站掉进 `article` 兜底。
- **选流策略**：通用站点「选最大」只对单视频页面安全；多视频页面（抖音/信息流）要选「当前在播/可见」，否则下错。
