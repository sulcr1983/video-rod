## 五、已知风险 / 副作用（**必须让审计知道**）

### 5.1 DNR 改 Referer 是全局副作用（本轮新增的行为）

`vrMedia.headers` → `vrSetMediaHeaders(domain, referer)` 会注册**会话级 DNR 规则**：

- 作用域：整个浏览器会话，不是单个标签页
- 生命周期：10 分钟后由既有 `vrClearMediaHeaders` alarm 自动清（`vrSetMediaHeaders` 原有逻辑）
- 影响：这 10 分钟内，**用户其他标签页**对同一图床域名的请求，Referer 都会被改成扫描页地址
- 规则池：12 条，同域名复用；新域名超限时**淘汰最早一条**（`vrHeaderRuleByDomain`）

风险等级：低（Referer 只影响防盗链判定，不改 Cookie/身份）。但这是**跨标签页的全局行为**，
审计要确认「能接受」而不是「没人知道」。

### 5.2 缩略图会触发真实网络请求

侧栏一打开就会预载最多 60 张图（`fillSizes`，2.5s 预算）+ 缩略图渲染。
对流量敏感的用户，打开侧栏 = 一次页面级请求量。这是既有行为（B-78 引入），本轮没变。

### 5.3 配额与风控（别踩）

- 真实登录态实例：`python tools/vr-session.py ensure --reason "..."`，JSON 在 `deliverables/test-runs/session-log.json`
- **上限 6 次/日 + 冷却 240s**（苏哥 2026-11-05 定的 EL-02/EL-03）；被拒时**不要绕过**
- 隔离套件（`e2e-all --isolated`）走独立 profile + 9490，**不占配额**、不碰登录态
- 真实登录态只许「只读、单页、不循环」（`docs/TESTING.md §0.0`，苏哥原话在文件里）

### 12.2 回收站复活：三条通道叠加（ADR-085）

| # | 位置 | 缺陷 |
|---|---|---|
| ① | `js/library/indexer.js` `build()` | 只对 `downloads` / `snapshot` 跳过 `state='trashed'`，`full` / `reconcile` 没跳过；原注释理由是「遍历磁盘扫到即存在，正常恢复」 |
| ② | `js/library/indexer.js` `mergeEntry()` | 结尾无条件 `out.state='ok'`，且对 `old.state==='trashed'` 主动清 `trashBatch/trashedAt/trashNoFile` —— 扫描替用户做了恢复 |
| ③ | `js/library/trash.js` `sweep()` | `exists(fsRel)` 判定排在 `trashNoFile` **之前**；refOnly 删除（同 sha256 另有活跃条目）文件本就留在原位，于是每次启动自愈都打回 `ok` |

**为什么历史结论说「不会复活」却被推翻**：`deliverables/reviews/2026-11-10-回收站清空后死卡复发诊断.md` §3.1 的实测是在「已清空」状态下跑四种扫描，漏掉了 `refOnly` 这一形态；普通删除的文件已搬进 `_回收站`，扫描确实扫不到，所以当时是绿的。

**修复**：删除态是权威，只有 `VRTrash.restore()` 能清除。`build()` 全模式跳过并计 `skippedTrashed`；`mergeEntry()` 纯字段合并；`sweep()` 先判 `trashNoFile`、回滚需「回收站无副本」；新增 f 段用清单+副本+mtime 把存量复活条目回打 `trashed`（`requarantined`）。

**验收**：`tools/cdp-trash-full-rescan-test.py` **18/18**；既有 `cdp-trash-empty-repro.py` **23/23**、`cdp-trash-dup-index-test.py` **9/9**（D2 证实「回收站无副本 + 原位有文件」仍能正常回滚）。

### 12.3 定位：file:// 标签页 ≠ 打开文件夹（ADR-086）

`revealWithoutDownload()` 原来把目录拼成 `file:///…/` 再用 `chrome.tabs.create` 打开 —— 那只是浏览器里的目录索引页。官方 API 只有 `downloads.show(downloadId)`（"Show the downloaded file in its folder in a file manager"，且只收 id）与 `showDefaultFolder()`（只能开默认下载目录）。

**修复**：删掉 `file://` / `tabs.create` / `window.open`；改为「同目录下载记录 show → showDefaultFolder → 复制路径」三级降级；`show()` 回调检查 `lastError`，失败即降级；文案区分三种结果。

**上限**：要按任意路径精确选中文件必须 native messaging 宿主（`explorer /select,`），已记 B-97 待苏哥决定是否接受安装成本。调研见 `docs/RESEARCH-TRASH-RESCAN-AND-REVEAL.md`。
