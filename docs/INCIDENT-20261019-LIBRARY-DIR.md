# 媒体库目录限制复盘（2026-10-19）

## 结论

“目录不对”限制来自**我们自己写的 `hasMediaEntries` 白名单**（`js/library.js`），不是浏览器、Windows 或磁盘权限限制。浏览器只要求一次用户手势授权；授权后目录可读可写。白名单属于过度设计，已删除。

## 直接原因

`pickRoot()` 在 `showDirectoryPicker()` 之后检查目录里是否存在 `x/weibo/douyin/xiaohongshu/instagram/小红书/微博/抖音`。不满足就清空句柄并弹：

> 目录不对：里面没有 x/微博/小红书 等媒体目录

这会把以下合法场景全部拒掉：

- 新建的空媒体库；
- 只有 `_index` 的初始化目录；
- 用户自定义的平台目录名；
- 选中的是父目录或某个平台子目录。

## 为什么折腾这么久

1. **把“提示”做成了“硬拒绝”**：本来只是想防止误选空目录，结果变成内容白名单。
2. **E/F 盘混淆**：F 盘 `video-rod` 早期只有 `_index`；E 盘 `personal/Downloads/video-rod` 才有文件。我们一直按 E 的实际文件解释，苏哥要的是 F，双方目标不一致。
3. **原生选择器窗口问题**：`showDirectoryPicker` 的窗口在 (0,0) 被星愿主窗口盖住，底部按钮被任务栏裁掉；这跟白名单是两件事，但叠在一起后每次选择都失败。
4. **外部下载目录污染**：F 盘里 `xbd-downloader`（704 个文件）和 `老黄的分享`（17 个微信图片/视频）被当成媒体库内容，扫描出 919 项，看起来“一塌糊涂”。
5. **重命名 API 差异**：星愿的 `FileSystemFileHandle.move(newName)` 抛 `NotAllowedError`；必须用 `move(父目录, 新文件名)`，与删除到 `_trash` 的签名一致。

## 教训

1. **目录选择不做内容白名单**；空目录是合法状态，最多给提示。
2. **区分“权限限制”和“产品校验”**，不要把后者的错误文案写成前者的口吻。
3. **先确认用户目标盘符**，不要拿“哪里有文件”反推“用户想用哪里”。
4. **媒体库只扫本扩展的目录结构**；外部下载器目录应隔离或显式跳过。
5. 原生选择器的窗口层级问题要独立排查，不能与业务校验混在一起。
