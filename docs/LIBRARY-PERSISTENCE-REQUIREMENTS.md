# 资源库持久化 — 需求规格

> 版本 v1.0 ｜ 日期：2026-11-07 ｜ 状态：**已确认（苏哥拍板方向）**
> 配套：`LIBRARY-PERSISTENCE-SPEC.md`（技术规格）、`LIBRARY-SELF-CONTAINED-PLAN.md`（架构方案）
> 上位：`REQUIREMENTS.md`（项目总需求）§P0 资源库部分

---

## 1. 为什么有这个需求

**一句话**：我的素材库，重装系统后整理成果（星标、标签、收藏夹、改的名字）不能丢。

### 1.1 背景事实（已实测，非推测）

| 事实 | 数据 | 来源 |
|---|---|---|
| 现在数据住在浏览器里，不在素材文件夹 | IDB `vr-library` vs 磁盘 `_library/index-*.json` | 代码核查 |
| 磁盘快照只有 9 个字段 | `relPath/size/mtime/platform/creatorId/type/fileName/starred/tags` | `indexer.js:744-756` |
| 收藏夹根本没进快照 | 只存 `setting` store 的 `vrFavs` | `app.js:1723/1746` |
| 缩略图只存 IDB blob | `thumb` store，无落盘、无删除接口 | `db.js:127/148/157` |
| 快照不会自动更新 | `VRIndex.snapshot()` 全仓库仅 1 个调用点（设置页手动按钮） | `settings.js:728` |
| 素材量级 | **上万条** | 用户确认 |

### 1.2 用户原话（本轮确认）

> 「假如重装系统了，但是素材库还是在的，文件夹里面都有。来个大扫描入库可以吗？」

> 「尽量把所有内容都保存在同一个文件夹下面，扫描先读那个单独的文件或者子文件夹，读取内容。包括数据库和缩略图等」

**这两句就是本需求的全部来源。** 下文所有条目都从这两句推导。

## 2. 用户故事

### US-1 重装后不丢整理成果（P0，核心）

**作为**唯一用户，
**我希望**重装系统后，把素材文件夹拷回来、装好扩展、授权一次目录，
**就能看到**所有素材 + 我加的星标、标签、收藏夹、改过的名字，
**这样**我不用担心哪天重装就白整理了。

**验收**：
1. 加星标 + 加标签 + 改名 + 建收藏夹 → 等 30 秒（自动写盘）
2. 关闭浏览器，删除整个 IndexedDB（模拟重装）
3. 重新打开 → 授权目录
4. **星标、标签、改名、收藏夹全部还在**，缩略图直接显示不用等

### US-2 缩略图跟着文件夹走（P0）

**作为**用户，
**我希望**缩略图存在素材文件夹里，
**这样**重装后不用对上万条素材重新解码（那要很久），也方便和素材一起备份。

**验收**：清空 IDB 后打开资源库，网格**立即有图**，CPU 无长时间满载。

### US-3 打开就能看到最新内容（P0）

**作为**用户，
**我希望**下载完新素材，下次打开资源库**就能看到**，
**而不是**必须先回设置页点一次「写快照」。

**验收**：下载 1 张图 → 不回设置页 → 重新打开资源库 → 能看到这张新图。

### US-4 上万条不卡（P0）

**作为**用户，我的库有上万条，
**我希望**打开资源库能快速出画面，不要每次启动都全量扫一遍目录。

**验收**：1 万条库冷启动 < 1 秒出画面；新增 1 个文件后打开，只处理那 1 个。

### US-5 超限要告诉我（P0）

**作为**用户，
**我希望**当素材超过系统上限时**明确提示**「超出部分未纳入」，
**而不是**悄悄少显示一部分让我以为素材丢了。

**验收**：库超过上限时，界面有明确文字提示与数量。

### US-6 整体拷走即备份（P1）

**作为**用户，
**我希望**把整个素材文件夹拷到移动硬盘，在另一台电脑上照样能用，
**这样**这就是我唯一的备份方案，不需要额外工具。

**验收**：整个文件夹拷贝到新机器 → 装扩展 → 授权 → 内容与整理成果完整。

## 3. 范围

### 3.1 做什么（In Scope）

| # | 内容 | 优先级 |
|---|---|---|
| R-1 | 快照补全字段（改名/分辨率/时长/来源 URL/原帖） | P0 |
| R-2 | 收藏夹写进快照 | P0 |
| R-3 | 快照自动更新（不再依赖手点） | P0 |
| R-4 | 固定名 `_library/index.json` + 路径能从它恢复 | P0 |
| R-5 | 缩略图落盘 `_library/thumbs/<hash>.webp` | P0 |
| R-6 | 缩略图生命周期管理（改名/删除/移动同步清理，无孤儿） | P0 |
| R-7 | 缩略图失效判定（mtime + size 双校验） | P0 |
| R-8 | 冷启动「先读索引出画面，再后台对账」 | P0 |
| R-9 | 超限提示（条数/目录深度），不再静默截断 | P0 |
| R-10 | 按需查询替代全量读表（`queryFiles`） | P1 |
| R-11 | 备份/恢复入口（导出/导入整包） | P1 |

### 3.2 不做什么（Out of Scope）

| 不做 | 原因 |
|---|---|
| **本地 HTML 版资源库** | 实测 `file://` 下画布污染（T15/T16），缩略图全灰；且它读同一份快照，救不了收藏夹/缩略图。见 `LIBRARY-STANDALONE-PLAN.md` §0 |
| 引入 SQLite / WASM | 明文 8MB / 580ms 已够用，WASM 增 1.5MB 且需放宽 CSP，收益为负 |
| 自行实现「临时文件 + rename」 | 标准 API 没有 rename（`FileSystemHandle.move()` 至今未发布），而 `createWritable()` 本身已是原子替换 |
| 依赖 `FileSystemObserver` 做唯一增量来源 | 提案明确不保证不丢事件，有 per-origin 上限，SW 生命周期短 |
| 多端同步 / 云备份 | 纯本地自用 |
| 改 IDB 版本做数据迁移 | 新字段是普通属性，schemaless 无需升版；快照是派生数据 |
| 缩略图压缩格式改造 | 现有 webp 0.66 / 400px 已实测可用 |

### 3.3 明确的取舍（用户已拍板）

| 取舍 | 决定 | 用户原话/依据 |
|---|---|---|
| 缩略图占用 200–500MB | **接受** | 「接受，缩略图落盘到 `_library/thumbs/`」 |
| 上万条重扫慢 | **改「读索引 + 增量对账」** | 「改成『读索引 + 增量对账』（推荐）」 |
| 做 HTML 还是修扩展 | **修扩展** | 「那其实不需要做 html 设计啊，我们把扩展这个完善就行了」 |

## 4. 约束（不可违背）

| 约束 | 说明 |
|---|---|
| 零新增依赖 | 不引入 SQLite/WASM/thumbhash 等；沿用原生 JS |
| 无构建链 | 按序 `<script>` 加载，不引入打包工具 |
| 数据可回滚 | 删掉 `_library/index.json` 不应影响任何现有功能 |
| 不阻断现有功能 | 缩略图落盘失败只降级，不影响浏览 |
| 不误删用户数据 | 沿用 ADR-030：扫不到的条目标 `missing`，永不自动删除 |
| 兼容旧数据 | 无 `schema` 键的旧快照必须能正常读 |

## 5. 验收（用户可感知的最终标准）

**全部满足才算完成：**

1. 加星标/标签/改名/收藏夹 → 等 30 秒 → 清空浏览器数据 → 重新打开 → **四项全在**
2. 清空浏览器数据 → 打开资源库 → **网格立即有图**，不用重新解码
3. 下载新图 → **不回设置页** → 重开资源库 → **能看到**
4. 1 万条库 → **1 秒内出画面**
5. 超过上限 → **有明确提示**，不是静默少显示

**回归底线**：现有测试全绿（`test-path` / `test-save` / `cdp-index-test` 35/35 / `--suite library`）。

## 6. 分阶段交付

| 阶段 | 内容 | 单独可验收 |
|---|---|---|
| **阶段 1** | 快照补全 + 收藏夹 + 自动化 + 固定名 + 路径恢复 | ✅ US-1、US-3 |
| **阶段 2** | 缩略图落盘 + 生命周期清理 + 失效判定 | ✅ US-2 |
| **阶段 3** | 冷启动读索引 + 增量对账 + 超限提示 | ✅ US-4、US-5 |
| **阶段 4**（可选） | 备份/恢复入口 + 按需查询 | ✅ US-6 |

**阶段 1 单独就有价值**：它直接解决用户的核心痛点（重装丢整理成果），
且改动最小、可回滚。建议先做。

## 7. 风险与用户可见影响

| 风险 | 用户会看到什么 | 缓解 |
|---|---|---|
| 快照写入拖慢批量下载 | 下载变慢 | 30 秒节流合并，不逐条写 |
| 缩略图落盘失败（磁盘满/无权限） | 无感知（仍能看） | 静默降级到会话内生成 |
| 收藏夹写进快照后两边不一致 | 可能出现两份收藏夹 | 以快照为恢复源，IDB 为运行时源，冲突时保留并集 |
| 超限提示打扰 | 顶部一条提示 | 只在首次出现时提示，可关闭 |
| 老快照被新代码误读 | 显示异常 | `schema` 缺失走兼容分支，缺字段用默认值 |
