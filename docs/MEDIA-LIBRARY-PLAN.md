# 钓鱼竿媒体库（Media Library）方案 v1

> 日期：2026-10-19 ｜ 状态：📋 方案 + 原型 ｜ 关联：ADR-035
> 目标：下载器 → 本地媒体库。文件用普通文件夹保存，网页端做 CMS；不引入服务器。

---

## 1. 一句话方案

下载统一落到 `平台/博主(@ID)/图片|视频/`，旁边维护一份 `_index/index.json`；扩展提供一个
`library.html` 管理页，用户选一次媒体根目录（File System Access API），即可在网页里搜索、
筛选、预览、播放、重命名、移动、删除，也可以直接打开系统文件夹查看。

## 2. 目录结构（普通文件夹，随时可脱离插件浏览）

```
Downloads/video-rod/                 # 用户可选根目录
├── weibo/
│   └── 史老柒(@1850017837)/
│       ├── images/
│       └── videos/
├── x/
│   └── NASA(@NASA)/
│       ├── images/
│       └── videos/
├── douyin/
│   └── 东方街拍(@22994771145)/videos/
├── xiaohongshu/
│   └── 小高(@5904068850c4b46b86967480)/images|videos/
├── instagram/
│   └── nasa(@nasa)/images|videos/
├── _index/
│   ├── index.json                   # 可移植主索引
│   └── thumbs/                      # 缩略图缓存
└── _trash/                          # 删除先移到这里，可恢复
```

命名：`标题或文案_序号.ext`；目录已带平台/作者，文件名不再重复作者前缀。
所有文件都是普通图片/视频，**不用数据库也能看**；库页只是增强体验。

## 3. 元数据

```json
{
  "id": "x:2111180963661435219",
  "platform": "x",
  "author": { "name": "NASA", "id": "NASA" },
  "type": "video",
  "title": "飞机阵容只会越来越壮大…",
  "desc": "",
  "tags": ["航天"],
  "file": {
    "path": "x/NASA(@NASA)/videos/飞机阵容_01.mp4",
    "ext": "mp4", "bytes": 8401119,
    "width": 1080, "height": 1920, "duration": 63.2
  },
  "source": { "pageUrl": "https://x.com/NASA/status/…", "mediaUrl": "https://video.twimg.com/…" },
  "savedAt": "2026-10-19T03:00:00+08:00",
  "thumb": "_index/thumbs/x_2111180963661435219.jpg"
}
```

- `_index/index.json` 为主索引；IndexedDB 做查询缓存。
- 写入采用「临时文件 + 覆盖」，避免半截 JSON。
- 索引丢失时可以从目录结构重建（平台/作者/类型/文件名），标题退化为文件名。

## 4. 技术选型

| 层 | 方案 | 理由 |
|---|---|---|
| 管理页 | 扩展托管 `library.html`（vanilla JS/CSS） | 不依赖外部服务、离线可用；避免 `file://` 的读取限制 |
| 文件访问 | File System Access API | 用户选一次根目录；可读写/删除/重命名；Chrome/Twinkstar 144 支持 |
| 目录句柄 | `FileSystemDirectoryHandle` 存 IndexedDB | 下次打开免重复选择；权限失效时在用户手势里重新申请 |
| 索引 | `_index/index.json` + IndexedDB 缓存 | 可移植、可人工查看；大库查询走缓存 |
| 播放 | `getFile()` → `URL.createObjectURL` → `<video>` | P1 简单可靠；大文件 P2 用 Service Worker 做 Range 流式 |
| 缩略图 | 图片 `createImageBitmap`；视频用 poster/首帧 | 网格不加载原片，性能好 |
| 搜索 | 内存索引过滤 | P1 够用；数据量大再考虑 SQLite WASM / MiniSearch |
| 删除/移动 | `removeEntry` / `move()`，不支持则复制+删除 | 删除先进 `_trash/`，二次确认 |

> 关键约束：File System Access 的目录句柄与 **origin** 绑定。内容脚本在 `m.weibo.cn` 选的目录，
> 扩展页不能直接复用。因此目录选择与写入统一放在扩展页/离屏上下文，或下载先落固定根目录
> 再由 library 整理。不要在每个站点各存一套句柄。

## 5. 页面信息架构（CMS）

**层级：媒体库 → 平台 → 博主 → 图片/视频 → 素材。** 平台和博主是父子关系，不做并列筛选。
左侧资源树直接镜像磁盘目录，用户是“逛文件夹”的心智，不是“填筛选器”。

```
媒体库
├─ 微博 (4)
│  ├─ 史老柒 (2)
│  │  ├─ 图片 (2)
│  │  └─ 视频 (0)
│  ├─ 安然cn (1)
│  │  └─ 视频 (1)
├─ X / Twitter (4)
│  ├─ NASA (3)
│  │  ├─ 图片 (0)
│  │  └─ 视频 (3)
│  └─ SpaceX (1)
├─ 抖音 (3)
├─ 小红书 (3)
└─ Instagram (3)
```

```
┌──────────────┬─────────────────────────────────────────────┬─────────────┐
│ 资源树        │ 面包屑：媒体库 / 微博 / 史老柒 / 图片          │ 详情检查器   │
│ 媒体库        │ 搜索 / 打开文件夹 / 重新扫描 / 选择模式        │ 大图/视频    │

│ │ │ └ 视频    │  卡片网格（缩略图、类型、时长、作者、标题）    │ 重命名/移动  │
│ │ └ 安然cn    │                                             │ 删除/在文件夹│

│ └ …           │                                             │             │

```

交互（参考 Eagle / PhotoPrism / Immich / Stash / XBD）：

- 树节点 = 文件夹：点平台看全部博主，点博主看全部素材，点图片/视频只换类型；面包屑可逐级返回。
- 网格卡片：缩略图 + 类型徽章 + 时长 + 作者 + 标题 + 日期 + 大小；hover 显示播放/选择。
- 详情查看器：大图/视频、**上一张/下一张**、键盘 `←/→`、`Esc` 关闭、`F` 最大化、图片 `+/-`/滚轮缩放。
- 批量：选择模式、全选当前、批量移动/删除。
- CMS：重命名、改标签、移动平台/博主、删除到回收站、复制路径、在系统文件夹打开。
- 空状态/加载/错误提示；删除必须二次确认。

> 搜索、类型快捷筛选只是“跳转/收窄”的捷径，主心智始终是资源树的层级；类型不是和平台/博主并列的一级导航。

## 6. 分期

| 阶段 | 内容 | 预估 |
|---|---|---|
| P1 | 目录规范 + `index.json` 写入 | 0.5–1 天 |
| P2 | library 只读：扫描/搜索/筛选/网格/详情/播放 | 2–3 天 |

## 7. 风险与边界

- 目录授权与 origin 绑定；换浏览器/重装后需要重新选目录。
- 大目录扫描性能：先懒加载 + 缩略图，必要时上索引缓存。
- HEVC 等编码能否播放取决于系统解码器；下载侧尽量保留 h264。
- 删除误操作：只进 `_trash/`，并二次确认；不做不可恢复的硬删除。
- 索引并发写：单写队列 + 原子替换；扫描与写入互斥。
- 不把签名接口/反爬逻辑放进媒体库；媒体库只管理已经落盘的文件。

## 11. 大量博主 / 内容的管理

目标：1 万级素材仍然顺滑，10 万级可检索；不把整库一次性塞进 DOM。

- **资源树懒加载**：平台默认折叠；展开后每平台先显示 Top 6 博主（按数量/最近更新），
  其余用「显示更多」；提供树内搜索（平台/博主/ID），输入 150ms 防抖。
- **收藏/置顶/最近**：常用博主可 Pin 到树顶；首页提供「最近下载 / 未看 / 收藏 / 重复」智能视图。
- **网格虚拟滚动**：只渲染视口附近卡片（windowing），滚动加载下一页；缩略图 `IntersectionObserver` 懒加载。
- **分页/游标**：按 `savedAt + id` 做游标分页（每页 100），不使用 offset 深分页。
- **索引分片**：`_index/platforms.json`（平台/博主计数）+ `_index/<platform>/<author>.json`（素材索引）；
  全局搜索另建 MiniSearch/FlexSearch 倒排索引；增量更新，不每次重扫全库。
- **搜索**：标题/描述/标签/博主/ID/路径；支持 `platform:weibo author:史老柒 type:video` 语法；防抖 + 结果高亮。
- **预览**：上一张/下一张只预取相邻 1–2 个（图片预加载、视频只取 metadata），避免批量拉流。
- **去重**：下载前按稳定媒体标识（平台+作品 ID+媒体 ID，URL 去签名参数）查账本；
  已存在直接跳过；同内容不同 URL 在入库/扫描时用 SHA-256 二次判定（详见 ADR-037）。
- **性能预算**：1 万素材首屏 < 1s、滚动 60fps；10 万素材用虚拟列表 + 分片索引 + 服务端式游标。
- **批量操作**：选择模式、全选当前结果、批量移动/删除；长任务显示进度，可暂停/继续。



> 结论：**不把完整 CMS 塞进扩展**。完整媒体库项目当 UX 参考；查看器/上传等小件用 MIT/Apache 组件。
> 新依赖按项目规则先给苏哥过目。

### 选型建议

1. **媒体库本体**：保持自研的资源树 + index.json；UX 参考 Immich/PhotoPrism/Stash，不复制 AGPL 代码。
2. **查看器**：优先接 **PhotoSwipe + Plyr**（MIT，许可证宽松，直接解决缩放/手势/播放/全屏）。
3. **文件浏览**：如果只想“打开文件夹看”，系统资源管理器足够；要 Web 文件管理可外挂 Filebrowser。
4. **不推荐**：把 Immich/PhotoPrism/Stash 嵌进扩展——它们有自己的数据库/导入/服务端，和“普通文件夹 + 可脱离插件浏览”的第一性原理冲突。
5. **许可证**：AGPL 项目只做参考；直接复用代码会带来网络 copyleft；MIT/Apache 组件可放心用。
