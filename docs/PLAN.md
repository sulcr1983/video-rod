## 一、需求审核结论

| 项目 | 结论 |
|---|---|
| 复刻 CocoCut 自用 | ✅ 合理。开源界有成熟同架构项目（猫抓），「复刻」= 在成熟底座上做个人化改造，不从零造轮子 |
| 不上架不进商店 | ✅ 合理且更简单（免商店审核、免开发者账号费），开发者模式 Load unpacked 在 2026 年 Chrome 依然是官方支持路径 |
| 新增 Plucker 式「自定义命名 + 下载到文件夹」 | ✅ 合理，且技术路线清晰（chrome.downloads 的 filename 支持「子目录/文件名」）。这是本方案相对猫抓原版的核心增量 |
| 原计划用 morluto/rea 研究 | ❌ 已纠偏：rea 是 AI 逆向工程工具套件，与视频下载无关。后续若遇到加密视频站点逆向，可拿它当显微镜 |
| 新增：自动最高清晰度 | ✅ **零开发**——猫抓多档选择界面默认就勾选最大带宽档；只需在设置里加个开关（可关、可改成"记住上次选择"） |
| 新增：下载网页图片 | 🔶 **需新开发**（猫抓嗅探类型清单里只有音视频，没有图片）——唯一的大增量，建议 P1；猫抓原有「右键保存单张图片」保留作兜底 |
| 新增：同页多 m3u8 合并 | ✅ **部分已有**：① 一个视频的几百个 ts 碎片 → 默认自动合并成完整 MP4（猫抓原生）；② 页面上多个不同视频 → 本就是不同内容，不该合并，批量分别下载即可；③ 一个视频被切成几个独立大段 → 可做「手动勾选按顺序拼接」（P1，自动判断归属不可靠故不做） |

## 二、竞品调研结论（Plucker XBD）

| 维度 | Plucker | 对本项目的借鉴 |
|---|---|---|
| 自定义文件名 | 每条媒体可改名字，支持按 X 用户名等维度命名 | ✅ 全盘借鉴：列表内联可编辑文件名 + 批量命名规则 |
| 自定义文件夹 | 不同来源的媒体进不同文件夹 | ✅ 全盘借鉴：每条可指定下载子目录，按站点/作者自动分Folder |
| 去重检测 | 记住已下载内容，跳过重复 | ✅ 借鉴：URL hash 记录，防手残重复下载 |
| 下载历史 | 可回看已下载媒体 | 🔶 P1（猫抓有基础，后补） |
| 侧边栏预览 | 即时预览当前页媒体 | 🔶 P1（猫抓已有 preview 页面，可接） |
| 站点范围 | 仅 X/Twitter（闭源，权限极简 3 个） | ➡️ 苏哥的钓鱼竿 = **通用全站嗅探**（猫抓底座）+ Plucker 的文件管理体验 |

**关键结论：Plucker 体验好但只服务 X；苏哥的钓鱼竿 = 猫抓的全站嗅探能力 × Plucker 的文件管理体验。**

## 三、功能设计（分级）

### P0（核心，第一版必须）
1. **全站视频嗅探**：m3u8/HLS、直链 mp4/webm、`<video>` 标签探测（猫抓原生能力，不改）
2. **清晰度选择**：m3u8 master playlist 解析出多档（猫抓原生）
3. **智能起名 + 自定义命名（Plucker 式）**：
   - **智能起名**（苏哥 10-17 拍板）：内置页面识别——文章页取文章大标题（自动剥掉「标题_网站名」尾巴）、推特页取推文正文（去「某人 在 X:」前缀、去引号、去 t.co 链接、换行压成空格）、认不出退回网页标题
   - **作者维度**（苏哥 10-17 追加拍板）：文件名带作者，格式 `昵称(@账号)_标题.ext`；作者来源：推特取 @handle + 显示名、小红书取作者卡片（昵称+小红书号）、文章页尝试署名；**拿不到作者就自动跳过该段**（不留空下划线）
   - **清洗规则**：非法字符（`\ / : * ? " < > |`）换成下划线；emoji 默认删除（嫌难看可改成保留）；换行压空格
   - **目录联动**（苏哥 10-17 拍板）：小红书/推特等平台默认按 `下载目录/平台/作者昵称/` 自动分文件夹，与文件名作者双保险；每条仍可手动改目录
   - **超长截断**：超过 60 字保留前 60 字加「…」（防止路径超系统上限导致下载失败）
   - **重名加序号**：同一页面多个文件同名时自动变 `标题_01`、`标题_02`
   - 列表每条内联文件名输入框，所见即所得；智能取名只是预填，随时可手动改/批量覆盖
   - 命名模板变量：`${title}`（智能标题） `${post}`（正文/推文全文） `${site} ${index} ${date} ${ext}`
   - 批量命名：对勾选条目套用规则
4. **下载到文件夹（Plucker 式）**：
   - 全局默认目录（相对浏览器下载目录，如 `video-rod/`）
   - 每条可单独指定子目录（如 `bilibili/`、`某UP主/`）
   - 最近使用的文件夹快速选择 + 新建文件夹
   - 平台页自动按作者分目录（小红书/推特）：`video-rod/小红书/昵称(@账号)/`
5. **批量下载**：勾选多条 → 一键全下，各自的名字和目录互不干扰；完成后面板内 toast 汇报（苏哥定：只要面板内提示，不上系统通知）
6. **m3u8 自动合并 MP4**（猫抓原生能力：一个流的全部 ts 碎片拼成完整文件）
7. **清晰度自动选最高**：多档时默认勾选最高带宽档（猫抓原生默认行为，纯确认）；设置里可关
8. **网页图片批量下载**（苏哥 10-17 定进 P0；抄图片下载类扩展通行四件套）：
   - 扫描：`<img>` + srcset 取最高分辨率 + `<picture>/<source>` + CSS 背景图 + 懒加载属性（data-src 等）+ shadow DOM + video 封面图
   - 过滤：小于 100×100 跳过（滤图标/装饰图）、去重、data URI 处理
   - 动态加载：MutationObserver 监听懒加载/无限滚动
   - 与视频同款卡片（改名/目录/批量）；配图命名可带所在文章标题
9. **右键秒存**（抄 Video DownloadHelper）：网页视频/图片上右键 →「苏哥的钓鱼竿下载这个」，不开面板，直接走智能起名+目录下载
10. **B站/YouTube 抓取**（2026-10-17 审计后改版：**嗅探增强，零签名对抗**）：
    - **改版原因**：原「WBI 签名 + playurl 主动抓取」前提已崩塌——bilibili-API-collect 2026-01-28 收律师函关停删码，BBDown 归档、哔哩下载姬/BiliTools 2026-07-06 同日收函关停，B站下载开源生态 2026 年集体团灭（律师函点名「突破登录态访问控制、绕过签名鉴权、抓取付费内容、强取最高清晰度」——正是本功能清单）；YouTube 2026-01 起强制 SABR+poToken，「没有 Chrome 扩展能可靠下载 YouTube 视频」，扩展是被打击最重的品类
    - **B站（P0，新路线）**：分P列表从页面 DOM/状态读取（**不调 API、不碰 WBI 签名**）→ 用户勾选 → 扩展驱动页面切换分P → 猫抓嗅探浏览器实际发出的 DASH 流（m4s 直链）→ 下载 + 合并；Referer 必须 `www.bilibili.com`
    - **YouTube（降级 P1）**：只走嗅探，能抓多少抓多少；不投入签名对抗。苏哥刚需时唯一稳路 = 猫抓内置 m3u8dl 协议外挂 N_m3u8DL-RE（本机成熟程序，⏳ 待苏哥定）
    - **登录态内容**：借浏览器 cookie，大会员/会员内容可下（浏览器能播放=请求已带 cookie=嗅探即得，天然支持）
    - **懒加载**：只抓已加载项，不自动滚动页面（苏哥定）
    - **兜底**：抓取失效自动退回「当前页已加载」嗅探模式（苏哥定），永远有得下
    - 两个解析模块相互独立，一家失效不影响另一家；设置里有开关可整体关掉
    - DRM 严密封锁站点（爱奇艺/腾讯/Netflix）**不做**（苏哥明确不要）
11. **快捷键唤起面板**（抄 VDH：默认 Alt+Shift+V，chrome.commands 官方机制，chrome://extensions/shortcuts 可改）

### P1（第二版）
8. 去重检测（URL hash，防重复下载）
9. 下载历史面板
10. 侧边栏模式（chrome.sidePanel，猫抓已有入口）
11. **网页图片批量嗅探下载**（唯一需新开发的大功能）：扫页面 `<img>`/`srcset`/背景图 + 后台抓 `image/*` 响应，小图过滤（跳过图标/头像/像素图），列表卡片与视频同款（改名/目录/批量），下载走现有管线自动带 Referer 防盗链
12. **多个独立 m3u8 手动顺序拼接**：勾选多个 m3u8 → 按列表顺序拼成一个文件（应对"一个视频被切成几个大段"的站点）

### P2（有余力再做）
13. 一键更新嗅探适配脚本（从上游 cherry-pick）
14. 直播录制入口

## 六、风险与限制（丑话说前面）

1. **DRM 加密站点**（部分爱奇艺/腾讯/Netflix）：全球无解，只能录制兜底（猫抓有录制脚本，P2）
2. **m3u8 自定义命名**比直链复杂（合并链路），列为重点测试对象
3. **fork 冻结风险**：猫抓价值一半在持续更新的站点适配脚本，改造策略 = 外壳改、内核不动，保留 cherry-pick 能力
4. Chrome 大版本更新可能重新禁用 unpacked 扩展 → 真掉了就重装一次，配置不丢（storage 在 profile 里）
