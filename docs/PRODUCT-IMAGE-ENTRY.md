# 产品方案 · 图片下载入口收敛与打扰治理

> 日期：2026-10-25 ｜ 提出人：Sunny 姐姐 ｜ 分析：产品视角
> 起因：实测反馈三条 ——
> 1. 页面上常驻的悬停下载图标「不方便」
> 2. 很小的图片（图标/按钮）也冒下载按钮，影响使用
> 3. 弹出的图片清单页，「关闭」和「×」都点不动
>
> 前两条已修（见 §2），第三条已修。**本文重点回答第四条：批量下载该不该留在页面上。**

---

## 一、用户的原话与我的判断

> 「图片批量下载很少用，还是保留在扩展程序里面好，需要的时候点扩展程序，再在页面探测，批量下载。你是产品经理。你觉得如何」

**我完全同意，而且这不是妥协，是更正确的产品结构。**

### 1.1 为什么同意

| 维度 | 常驻浮标（现状） | 收进扩展（建议） |
|---|---|---|
| 打扰成本 | **每次浏览每个页面都打扰**，即使 99% 的时间不需要 | 0 打扰，只有主动点扩展时才出现 |
| 使用频率匹配 | 批量下载是低频操作，却占了常驻 UI 位 | 低频操作藏在两级入口后，符合成本匹配 |
| 页面污染 | 浮标 + 悬停条 + 面板，三层 UI 压在别人的网站上 | 页面上只剩悬停单张（也是可选关） |
| 站点兼容风险 | 浮标可能被站点 CSS/遮罩干扰（微博就出现过） | 扩展弹窗是扩展自己的页面，不受站点影响 |
| 认知负担 | 用户得知道「右下角那个圆点是什么」 | 点扩展 = 找功能，符合既有心智 |

### 1.2 更关键的一点：**入口早就在扩展里，而且功能是完整的**

`popup.html:83` 有按钮：

```html
<button class="fchip vr-imgbtn" id="vrScanImages" title="扫描本页所有图片，批量保存">抓图</button>
```

绑定在 `js/popup-videorod.js:1214 bindImageScan()`：
点「抓图」→ 扫描本页 → 弹出图片网格 → 勾选 → 批量保存。**功能是完整可用的。**

> ⚠️ 我最初判断它是「死按钮」，**那是错的**：我只 grep 了 `popup.js`，实际代码在
> `popup-videorod.js`。**教训：下「没有引用」这种结论前必须全仓搜。**

所以真正的问题是：**扩展里已有入口，但页面上的浮标又提供了一个更显眼的入口，
用户自然走浮标那条路，于是「低频功能」变成了「常驻打扰」。**

修法不是「再加入口」，而是**把浮标的默认值关掉**，让用户回到扩展那条路。

## 二、已经修好的三条（本轮）

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | 小图也冒按钮 | 只判 `naturalWidth`，一张 640×480 的图标被 CSS 缩成 16px 显示仍然通过 | 改判**显示尺寸**：短边 < 48px 不认；长宽比 > 6:1 的条状图不认 |
| 2 | 面板 ×/关闭点不动 | `closePanel` 里先调 `toggleSettings(false)` → 走 `renderAll()`，一旦抛错，后面摘 `mask.on` 的代码永远不执行 | 先摘面板和遮罩，再收设置区，且包 try/catch |
| 3 | 悬停按钮「先出现再跳一下」，点下去点空 | `show()` 里先 `add('on')` 显示、再算「全部 N」文案、再定位 —— 文案变宽后按钮已按旧宽度定位过 | 显示时先 `opacity:0`，等文案+定位定稿再显形 |

> 三条都有回归测试：`tools/cdp-image-hover-hit-test.py`（26 条）+ 原 I1/I2（34 条）。

## 三、建议的产品结构（核心提案）

### 3.1 三层降级，按「使用频率」分配 UI 成本

```
高频、即时  ──→  悬停单张下载（页面上，可关，默认开）
                  用途：看到一张图想存下来。零点击成本，值得常驻。

低频、批量  ──→  扩展弹窗「抓图」（两级入口）
                  用途：整页/整相册保存。需要主动找，符合频率。

极低频、管理 ──→  资源库页面（已存在）
                  用途：看已下载的、删除、重命名。
```

### 3.2 具体改动

**① 去掉页面右下角浮标（`imgPanel` 默认改为 `false`）**

理由：浮标是「常驻 UI」，但它服务的是低频的批量功能。这是成本错配。
保留代码（用户可在设置里开回来），只是**默认关**。

**② 把扩展弹窗的「抓图」按钮真正接上**

点「抓图」→ 向当前标签页注入扫描 → 直接在**扩展弹窗里**列出图片网格 → 勾选 → 批量下载。
这样用户全程不需要页面上的浮标，且弹窗是扩展自己的页面，不受站点 CSS 干扰。

**③ 悬停单张保留，但增加「智能静默」**

- 小图/图标/条状图不出（已修）
- 同一站点连续悬停 5 次都没下载 → 本次会话该站点降低触发频率（可选，后续做）
- 用户可一键关掉（设置里已有）

### 3.3 为什么不干脆把悬停也去掉？

因为**悬停单张是高频操作，且成本极低**（不点任何按钮，鼠标停一下就行）。
它的问题是「误伤小图」，不是「不该存在」——修好误伤就够了。

而批量是低频，浮标是常驻 UI，这才是错配。

| 步 | 内容 | 风险 |

**两家都不在页面上放常驻下载入口。**

另外发现我们技术上的一个**优势**：微博那种防盗链 403，
这两家都没真正解决（IDC 靠 canvas 重编码、Image Harvest 文档没提），
而我们的「页面上下文 fetch」更对症。

## 五、给 Sunny 姐姐的一句话总结

**你的判断是对的，而且比「加个开关」更进一步：**
批量下载的入口本来就在扩展里（那个「抓图」按钮），只是**从来没接上过**。
所以正确的做法不是「再设计一个入口」，而是**把已经存在的那个接上，然后把页面上的浮标默认关掉**。

这样：
- 页面上只剩「悬停单张」，且不再误伤小图 → 不打扰
- 想批量时，点扩展 → 抓图 → 勾选 → 下载 → 符合「需要时才出现」
