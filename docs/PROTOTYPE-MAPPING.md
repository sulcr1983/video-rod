# 原型 → 代码 落地映射（媒体库重设计）

> 版本：v1.0 ｜ 日期：2026-11-04 ｜ 状态：待苏哥确认原型后进入施工
> 原型：`deliverables/prototypes/media-library-redesign-v1.html`
> 代码基线：`merge/remote-20261104`（合并后，媒体库为模块化版本 `js/library/` 17 个模块）
> 本文解决一个具体问题：**原型是"纸上的目标状态"，代码是"已实现的一部分"，中间必须先有一张对照表，否则落地时会重复做、做错、漏做。**

---

## 0. 一句话结论

原型不是从零画的新东西——**代码已经实现了原型里约六成的结构**，但两者用的是两套命名（原型 `pv*`、代码 `lib*`），而且**代码里有一批原型没画的功能（回收站、右键星标、创作者导航），直接照原型改会把它们弄丢**。

所以落地不是"照原型重写"，而是三件事：**改视觉、补缺口、别弄丢已有的**。

### 2.1 「分辨率」是唯一一次能拿到真值的机会

查证结果：

- `js/library/db.js:145` 的 `putThumb(thumbKey, blob, w, h)` —— 存的是 **canvas 尺寸（缩放后）**，不是原图尺寸
- `js/library/indexer.js` —— **全文件没有一行写入 `width` / `height`**（只有 `mergeEntry` 负责"保住旧值"，但从来没人写过）
- `js/library/thumbs.js:124/128` —— 生成缩略图时**能看到 `naturalWidth` / `videoWidth`**，也就是真实分辨率，但只用来算 canvas 比例，没回写条目

**这意味着：分辨率不是"取不到"，是"看到了没存"。**

而索引一旦建完，之后不会再解码每个文件——**错过生成缩略图那一刻，以后只能重新解码全库才能补回来**。

所以这条要**趁现在顺手补**，改动量一行：

```js
// thumbs.js 生成成功后，把真实宽高回写到条目
entry.width = w; entry.height = h;   // w/h 取 naturalWidth / videoWidth，不是 canvas 的
```

## 6. 「标签」到底是丢了还是没丢

我上一轮跟苏哥说"标签功能丢了"，**这句话不准确，纠正如下**：

| 层 | 现状 |
|---|---|
| 数据库字段 | ✅ **有**：`indexer.js:228` 的 `tags: []`，`db.js` 建了索引 |
| 重建索引时保留 | ✅ **有**：`mergeEntry` 显式保住 `old.tags` |
| 读写接口 | ❓ 待确认（`db.js` 是否有按标签查） |
| **界面入口** | ❌ **没有**：信息栏没有标签区，卡片不显示标签 |

**结论：不是"丢了"，是"只有仓库没有货架"。** 补一个标签区（原型已有设计）+ 写入接口即可，成本远小于重做。

同理**查重（SHA-256）**：本地单文件版有，模块化版没有。查重需要读完整个文件算哈希，成本高，建议列为独立任务，不塞进这次界面改造。

## 11. 原型的交互断言（2026-11-04 实测，非"看起来能点"）

原型不只是静态图，关键交互都跑过断言，结果如下（浏览器实测，0 JS 错误）：

| 断言 | 操作 | 实测结果 |
|---|---|---|
| 初始态 | — | 32 文件 / 回收站 3 项 |
| 右键删除 | 卡片右键 → 移到回收站 | 文件 32→31、回收站 3→4、标题同步「31 项」 |
| 恢复 | 抽屉内点恢复 | 回收站 4→3、文件 31→32、抽屉保持打开 |
| 星标 | 右键 → 加星标 | `starred` false→true |
| 清空 | 清空回收站 | 回收站 0、显示空态 |
| 列表表头 | 切列表 | 表头「名称/平台/作者/大小/保存」5 列，日期取真实 `dlAt`（11-04 / 11-03），不再写死 |
| 类型计数 | — | 图片 12 + 动图 6 + 视频 14 = 32，与总数自洽 |

> **一条教训**：中途我两次从截图里"读出"数字对不上（侧栏 27 vs 标题 32、12+14+14=40），实测都是**看图看错**——实际 32 和 12+6+14。涉及数字一律用 DOM 断言，不靠肉眼读图。
