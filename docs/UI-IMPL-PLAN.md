## 一、先讲一件最容易踩的事

**原型和代码是两套命名，类名不能直接搬。**

| | 原型 | 代码（真实） |
|---|---|---|
| 卡片 | `.card` | **`.ccard`** |
| 缩略图 | `.thumb` / `.cover` | **`.c-thumb`** |
| 标题 | `.title` | **`.c-name`** |
| 作者 | `.authorline` / `.avatar` | **`.c-creator`** + `.avatar` |
| 大小 | `.size` | **`.c-size`** |
| 时间 | `.timecell` | **`.c-date`** |
| 平台 | `.badge` / `.platcell` / `.dot` | **`.c-plat`** + `.pdot` |
| 时长 | `.duration` | **`.dur`** |
| 列表行 | `.card`（list 模式） | **`.row-main`** / `.row-name` / `.row-creator` / `.row-date` / `.row-acts` |
| 信息栏字段 | `.pi-item` / `<dt><dd>` | **`.fact`**（`lightbox.js` 里只有 4 个类名） |
| 批量勾选 | `.selbox` | **`.batch-check`** |

**规模：** `ui.js` 里有 **51 个**动态生成的 class、`library.html` 有 **117 个**。

> **结论：直接把原型的 CSS 复制过去，一条都不会生效。** 必须按上表把样式写到真实类名上。这是本次改造最容易返工的地方，写在第一条。

## 三、改造策略：三步，顺序不能反

### 第 1 步：只换设计令牌（风险接近零）

`css/library.css` 顶部一般是 `:root` 变量。**先只改变量，结构一行不动**：

| 令牌 | 现在 | 改成 | 影响 |
|---|---|---|---|
| 主色 | `#1677ff`（亮蓝） | `#16181D`（近黑，与 popup 统一） | 按钮、选中态 |
| 强调 | — | `#337CCC` | 链接、焦点环 |
| 圆角 | 混用 | `--r-sm 7px / --r 10px / --r-lg 14px` | 全局 |
| 阴影 | 混用 | `--sh-1/2/3` 三档 | 卡片、抽屉、菜单 |
| 字体 | 未统一 | 系统栈 + `tabular-nums` | 数字对齐 |

**为什么先做这一步**：能拿到约 70% 的视觉提升，改动只有几十行，**可以单独回退**。

### 第 2 步：按映射表逐组件改样式

按表把新样式写到真实类名上。顺序：**卡片 → 列表 → 侧栏 → 顶栏 → 预览层**。

**每改一个组件，立刻在真机看一眼**，不要五个一起改完再看。

### 第 3 步：改结构（只改必要的）

| 改动 | 文件 | 原因 |
|---|---|---|
| 列表加表头 | `library.html` + `ui.js:tableHtml()` | 现在没有表头，五列对不齐 |
| 信息栏改分组 | `lightbox.js:paintFacts()` | 现在 12 项平铺，改成"文件 / 来源"两组 |
| 图标换内联 SVG | `library.html` + `ui.js` 的 emoji | 现在用 emoji 和字符（`⌕ ☰ ▦`），跨平台不一致 |

## 五、数据结构变更

| 变更 | 位置 | 需要迁移吗 |
|---|---|---|
| `width` / `height` 写入条目 | `indexer.js` 的 `entryFromRel`；`thumbs.js` 生成后回写 | **不需要**，老条目为空，显示 `—` |
| 溯源字段 `pageUrl` / `authorUrl` / `authorId` / `workId` / `mediaUrl` / `dlAt` | IndexedDB 的 `file` 条目 | **不需要**，缺就显示"未记录" |
| `authorHandle` / `authorUid` / `authorState` | 同上 | **不需要** |

**关键**：新字段必须加进 `mergeEntry()` 的保留白名单，否则**重建索引一次就全丢**。这是最容易漏的一条。

## 六、明确不做的

| 项 | 原因 |
|---|---|
| 虚拟滚动 / 首屏分页 | 实测 5 万条要渲 65 万节点，**确实需要**，但它会把"全量内存数组"模型整个换掉（`all` 被 5 个函数依赖），**单独立项，不混进换皮** |
| 引 Media Chrome | 现有 8 个控件已接好事件，引库等于替换能用的东西 |
| 引 PhotoSwipe / lightGallery | 现有预览器已覆盖八成，且要接管我们的信息栏和胶片条 |
| 引 CSS 框架 | 项目零构建，且会砸掉 117 个 id / 51 个 class 的钩子 |
| webfont | 中文界面用系统字体栈才对 |

## 九、一句话总结

**原型能用，但它的类名和代码是两套，所以"照着改"不是"照着拷"。**

改造分三步走：先换令牌（低风险、单独回退）→ 再按映射表逐组件换皮 → 最后只改必须改的结构。共 9 个批次，批次 0（实机验证）不过就不开工。
